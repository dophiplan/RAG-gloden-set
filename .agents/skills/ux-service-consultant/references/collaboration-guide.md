# 타 에이전트 협업 가이드

## 1. Architect Agent와의 협업

### 1.1 개발 요청 시 필요 정보
```markdown
## 개발 요청서 (Architect Agent 전달)

### 문제 요약
- **위치**: 파일 경로 + 라인 번호
- **현재 동작**: 무엇이 문제인지
- **기대 동작**: 어떻게 되어야 하는지
- **심각도**: P0/P1/P2/P3

### 수정 방안 (선택사항)
- **제안하는 해결책**: 구체적인 구현 아이디어
- **대안**: 다른 가능한 해결책

### 영향 범위
- **수정 필요 파일**: 
- **연관 파일**: 사이드 이펙트 가능성이 있는 파일
- **API 변경 필요**: Y/N
- **DB 변경 필요**: Y/N

### 테스트 포인트
- **확인해야 할 시나리오**:
- **회귀 테스트 필요 여부**: Y/N
```

### 1.2 개발 완료 후 확인사항
```markdown
## 개발 완료 검증 (Architect Agent → UX Consultant)

### 구현 확인
- [ ] 요구사항이 모두 반영되었는가?
- [ ] 새로운 사이드 이펙트는 없는가?
- [ ] 코드 스타일이 일관된가?

### QA 전달사항
- [ ] 테스트 필요 범위

```

## 4. 협업 워크플로우

### 시나리오 1: 문제 발견 → 개발 → 검증
```
UX Consultant
    ↓ (문제 발견)
    ↓ 분석 및 분류
    ↓
Architect Agent ← (개발 요청서)
    ↓ 개발
    ↓
UX Consultant ← (구현 확인)
    ↓
QA Agent ← (테스트 요청서)
    ↓ 테스트
    ↓
UX Consultant ← (결과 검토 및 릴리즈 결정)
```

### 시나리오 2: 전체 서비스 점검
```
Main Agent
    ↓ (요청)
    ↓
UX Consultant
    ↓ 전체 플로우 분석
    ↓
    ├──→ Architect Agent (개발 필요사항)
    │       ↓ 개발
    │       ↓
    └──→ QA Agent (테스트 필요사항)
            ↓ 테스트
            ↓
    UX Consultant ← (종합 보고서)
    ↓
Main Agent
```

## 5. 커뮤니케이션 규칙

### 5.1 우선순위 정의
- **P0**: 서비스 사용 불가, 즉시 수정 필요
- **P1**: 주요 기능 장애, 빠른 수정 필요
- **P2**: UX 저하, 계획된 수정 필요
- **P3**: 개선사항, 선택적 수정

### 5.2 정보 우선순위
가장 중요한 정보를 먼저 전달:
1. 문제 요약 (한 문장)
2. 영향 범위 (사용자/기능)
3. 구체적인 위치 (파일/라인)
4. 재현 방법
5. 제안하는 해결책

### 5.3 금지사항
- 추측성 보고 (코드 확인 전)
- 과도한 기술 용어 사용
- 불분명한 책임 소재
