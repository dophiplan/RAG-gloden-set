# 💬 커뮤니케이션 규약 정책
## Communication Protocol for Team Collaboration

**버전:** 1.0  
**생성일:** 2026-03-15  
**목표:** 명확하고 효율적인 커뮤니케이션

---

## 🎯 핵심 원칙

### 1. 명확성 (Clarity)
- 모호한 표현 금지
- 구체적인 예시 포함
- 예상 결과 명시

### 2. 적시성 (Timeliness)
- 블로커 즉시 공유
- 진행상황 2시간마다 업데이트
- 완료 후 즉시 보고

### 3. 투명성 (Transparency)
- 문제 숨김 금지
- 실패 공유 환영
- 학습 내용 공유

---

## 📢 커뮤니케이션 채널

### 1. 일상적 질문/답변
```
채널: GitHub Issues / PR 코멘트
응답 시간: 2시간 이내
형식: 자유
```

### 2. 긴급 문제
```
채널: Slack @channel / Discord
응답 시간: 30분 이내
형식:
  [긴급] 간략한 설명
  - 영향 범위:
  - 조치 필요:
```

### 3. 의사결정 필요
```
채널: GitHub Discussion / 정기 미팅
응답 시간: 24시간 이내
형식: 의사결정 템플릿 사용
```

### 4. 문서/지식 공유
```
채널: GitHub Wiki / Notion
형식: 표준 문서 템플릿
```

## 📝 질문하기 (Question)

### 좋은 질문의 예

**❌ 나쁜 예:**
```
"이게 안 돼요"
"에러 났어요"
"도와주세요"
```

**✅ 좋은 예:**
```
"[문제] Type Error 2305 발생

환경:
- 브랜치: feature/PILOT-123
- Node: 22.5.1
- OS: macOS 14.5

에러 메시지:
Module '"./audit_log_batch_processor"' has no exported member 'ValidationResult'

시도한 것:
1. npm install 재실행
2. 파일 경로 확인
3. TypeScript 재시작

질문:
ValidationResult를 export하는 다른 방법이 있나요?"
```

### 질문 템플릿
```markdown
## 문제 요약
한 줄로 요약

## 환경
- 브랜치:
- Node 버전:
- OS:

## 에러 메시지/스크린샷
```
에러 내용
```

## 시도한 것
- [ ] 시도 1
- [ ] 시도 2

## 질문
구체적인 질문 내용
```

## 📊 진행상황 보고 (Progress Report)

### 2시간마다 업데이트
```markdown
## 진행상황 - 14:00

### 완료된 것
- [x] 항목 1
- [x] 항목 2

### 진행 중
- [ ] 항목 3 (50%)

### 블로커
- 없음 / 있음 (설명)

### 다음 2시간 계획
- 항목 3 완료
- 항목 4 시작

### 예상 완료 시간
- 18:00 (±30분)
```

### 일일 종료 보고
```markdown
## 일일 보고 - 2026.03.15

### 오늘 완료
1. 항목 A
2. 항목 B

### 내일 계획
1. 항목 C
2. 항목 D

### 이슈/리스크
- 없음 / 있음

### 필요한 것
- 없음 / 리뷰 / 결정
```

## 🚨 블로커/이슈 공유

### 즉시 공사항
```markdown
🚨 [블로커] 간략한 제목

**발견 시간:** 14:30
**영향:** 작업 진행 불가 / 일정 지연 예상
**긴급도:** 높음/중간/낮음

**상세:**
발생한 문제 설명

**시도한 것:**
- 시도 1
- 시도 2

**필요한 것:**
- @role 도움 필요
- 의사결정 필요
```

### 공유 후 조치
1. **즉시:** 채널에 공유
2. **15분:** 담당자 언급
3. **1시간:** 해결 안 되면 에스컬레이션
4. **해결 후:** 원인/해결책 공유

## 👥 에이전트 호출 규약

### 호출 형식
```
@role [긴급도] 질문/요청

예시:
@security [높음] 이 코드에 SQL Injection 가능성이 있나요?
@data Dual Write 데이터 정합성을 검증해주세요
@qa [긴급] 배포 전 테스트 커버리지 확인 부탁드립니다
```

### 응답 시간
| 긴급도 | 응답 시간 | 예시 |
|--------|----------|------|
| 🔴 Critical | 30분 | 장애, 보안 이슈 |
| 🟠 High | 2시간 | 기능 블로커 |
| 🟡 Medium | 4시간 | 일반 질문 |
| 🟢 Low | 24시간 | 개선 제안 |

### 다중 호출
```
@architect @security @data
Pilot Phase 2 설계 검토 부탁드립니다.

검토 포인트:
1. 아키텍처 적절성
2. 보안 취약점
3. 데이터 정합성
```

## 🚫 지양할 것

| 행동 | 이유 | 대안 |
|------|------|------|
| "됐다/안 됐다"만 | 원인 파악 불가 | 구체적인 에러 메시지 |
| DM 남용 | 팀 투명성 저하 | 공개 채널 |
| 읽씹 | 불확실성 증가 | "확인 중"이라도 응답 |
| 긴 텍스트 | 핵심 파악 어려움 | 요약 + 상세 링크 |
| 주관적 표현 | 오해 발생 가능 | 객관적 사실 |
