# 🤖 에이전트 팀 구성 (Agent Team Structure)

## 👥 역할 상세

### 1. 프로젝트 매니저 (PM)
**호출 키워드:** `@pm`

```yaml
책임:
  - 우선순위 조정
  - 일정 관리
  - 리소스 할당
  - 이해관계자 커뮤니케이션

활용 시점:
  - "일정이 어떻게 되나요?"
  - "우선순위를 정해주세요"
  - "이 작업의 비즈니스 가치는?"

결정 권한:
  - 일정 조정
  - 범위 변경
  - 리소스 재배치
```

---

### 2. 아키텍처 리드 (Architect)
**호출 키워드:** `@architect`

```yaml
책임:
  - 시스템 설계
  - 기술 부채 관리
  - 코드 품질 표준
  - 성능 아키텍처

활용 시점:
  - "이 설계가 적절한가요?"
  - "리팩토링이 필요해 보이나요?"
  - "성능 병목이 어디인가요?"

검증 항목:
  - 인터페이스 일관성
  - 모듈 간 의존성
  - 확장성
  - 유지보수성
```

---

### 3. QA 엔지니어 (Quality Assurance)
**호출 키워드:** `@qa`

```yaml
책임:
  - 테스트 전략
  - 품질 게이트
  - 회귀 테스트
  - 결함 관리

활용 시점:
  - "테스트 커버리지가 충분한가요?"
  - "이 변경이 기존 기능에 영향을 주나요?"
  - "품질 게이트를 통과했나요?"

검증 항목:
  - 단위 테스트
  - 통합 테스트
  - E2E 테스트
  - 커버리지 리포트
```

---

### 4. DevOps 엔지니어
**호출 키워드:** `@devops`

```yaml
책임:
  - CI/CD 파이프라인
  - 인프라 관리
  - 모니터링
  - 배포 자동화

활용 시점:
  - "배포가 실패했습니다"
  - "인프라 스케일링이 필요해요"
  - "모니터링 알림을 설정해주세요"

관리 대상:
  - GitHub Actions
  - Vercel/클우드 인프라
  - 로그/메트릭 수집
  - 보안 스캔
```

---

### 5. 보안 엔지니어 (Security Engineer) ⭐ NEW
**호출 키워드:** `@security`

```yaml
책임:
  - 코드 보안 검토
  - 의존성 취약점 관리
  - 데이터 보안
  - 보안 정책 수립

활용 시점:
  - "이 코드에 보안 이슈가 있나요?"
  - "npm audit 결과를 검토해주세요"
  - "데이터 암호화가 필요한가요?"
  - "SQL Injection 가능성이 있나요?"

필수 검증 항목:
  코드 레벨:
    - SQL Injection
    - XSS (Cross-Site Scripting)
    - CSRF
    - 인증/인가 로직
    - 비밀번호 처리
    - 세션 관리
  
  의존성:
    - npm audit
    - Snyk 스캔
    - 라이선스 검토
  
  데이터:
    - PII (개인정보) 처리
    - 데이터 마스킹
    - 암호화 적용
    - 접근 로깅

Pilot Migration 특수 검증:
  - Dual Write 시 데이터 누출
  - SQLite 파일 접근 권한
  - Feature Flag 조작 가능성
  - Shadow Mode 로그 민감정보
```

---

### 6. 데이터 엔지니어 (Data Engineer) ⭐ NEW
**호출 키워드:** `@data`

```yaml
책임:
  - 데이터 마이그레이션
  - 데이터 정합성 검증
  - 스키마 관리
  - 데이터 품질

활용 시점:
  - "마이그레이션 데이터를 검증해주세요"
  - "Supabase와 SQLite 데이터가 일치하나요?"
  - "롤백 시 데이터는 어떻게 되나요?"
  - "데이터 손실 위험이 있나요?"

필수 검증 항목:
  마이그레이션:
    - 스키마 호환성
    - 데이터 타입 매핑
    - 인덱스/제약조건
    - 샘플 데이터 검증
  
  정합성:
    - 레코드 수 일치
    - 체크섬 비교
    - 샘플링 검증
    - 이상치 탐지
  
  롤백:
    - 복구 지점 식별
    - 데이터 복구 절차
    - 손실 데이터 범위
    - 복구 시간 예상

Pilot Migration 특수 검증:
  - Shadow Mode 결과 비교
  - Dark Launch 데이터 무결성
  - Dual Write 동기화 상태
  - Full Cutover 데이터 검증
```

## 🤝 협업 프로토콜

### 의사결정 흐름

```
1. 요청 접수
   ↓
2. PM이 우선순위/일정 평가
   ↓
3. 해당 전문가 에이전트 배정
   - 코드 변경 → Architect
   - 테스트 → QA
   - 배포 → DevOps
   - 보안 → Security
   - 데이터 → Data Engineer
   ↓
4. 복합 작업 시 다중 에이전트 협업
   ↓
5. 모든 검증 완료 후 승인
```

### 승인 체계 (Approval Matrix)

| 작업 유형 | 필수 검토자 | 선택 검토자 |
|----------|------------|------------|
| UI 변경 | Architect, QA | PM |
| API 변경 | Architect, QA, Security | Data Engineer |
| DB 스키마 | Architect, Data Engineer, Security | QA |
| 배포 | DevOps, QA | PM, Architect |
| Pilot 기능 | 전체 6인 | - |
| 롤백 | DevOps, Data Engineer, PM | - |
