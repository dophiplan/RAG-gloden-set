## 📋 개요

### 문제 배경
현재 데이터 마이그레이션 프로세스는 다음 문제들이 있습니다:
1. **버전 필드**가 불필요하게 존재
2. **버전별 필드 매핑**이 꼬일 수 있음
3. **휴지통**이 행 전체를 삭제함 (셀 단위 삭제 필요)
4. **용어집**에 자동으로 데이터가 들어감 (선택적 추가 필요)
5. **네비게이션**이 불편 (이전/다음만 존재)

### 목표
제품마다 다른 Excel 포맷을 지원하면서 데이터를 정확하게 번역관리/용어집에 넣는 프로세스 구축

## 📐 상세 명세

### Step 1: 업로드 (UploadStep)

**기능**:
- ✅ 파일 업로드 (CSV, XLSX, XLS)
- ✅ 제품 선택 (필수) - 미선택 시 다음 단계 진행 불가

- Excel 시트명을 **버전명**으로 자동 인식

### Step 2: 필드 매핑 (MappingStep) - 핵심 변경사항

**핵심 제약**: **한 시스템 필드는 하나의 버전에만 매핑 가능**

**예시**:
- v1.0.0의 "원문" 컬럼 → 시스템 "원문" 매핑 ✅
- v2.0.0의 어떤 컬럼도 → 시스템 "원문" 매핑 ❌ (차단)

**버전별 순환 매핑**:
- 왼쪽: 버전 탭 (v1.0.0, v2.0.0)
- 중앙: 파일 컬럼 목록
- 오른쪽: 시스템 필드 드롭존

**시각적 피드백**:
| 상태 | 색상 | 설명 |
|------|------|------|
| 매핑 가능 | 초록색 | 현재 버전에서 매핑 가능 |
| 이미 매핑됨 | 회색 + 체크 | 현재 버전에 이미 매핑됨 |
| 다른 버전에서 사용 중 | 빨간색 + 자물쇠 | 다른 버전에서 사용 중 (드래그 불가) |

### Step 4: 분류 (ClassifyStep)

**기능**:
- ✅ 행별 액션: 용어집 / 번역관리 / 제외
- ✅ **지통**: 행 삭제 또는 **셀 삭제** 선택 가능
- ✅ **용어집**: 행별 선택 (일괄 처리 가능)
- ✅ 중복/유사 표시 (행마다 개별 표시)

**액션 타입**:
| 액션 | 설명 | 결과 |
|------|------|------|
| 📖 용어집 | 용어집으로 분류 | glossary 테이블에 저장 |
| ✓ 번역관리 | 번역관리로 분류 | translations 테이블에 저장 |
| ⏭️ 제외 | 무시 | 저장하지 않음 |
| 🗑️ 삭제 | 휴지통 | 완전히 제외 |

**지통 동작**:
```
🗑️ 클릭 시 옵션:
├─ 1. 해당 셀만 삭제 (선택한 필드 값만 제거)
└─ 2. 행 전체 삭제 (이 행을 import에서 완전히 제외)
```

## 🏗️ 기술 설계

### 상태 관리: React Context + useReducer

```typescript
// contexts/MigrationContext.tsx
interface MigrationState {
  currentStep: MigrationStep;
  completedSteps: Set<MigrationStep>;
  
  // Step 1
  file: File | null;
  productCode: ProductCode | null;
  detectedSheets: SheetData[];
  
  // Step 2
  versionMappings: Record<string, FieldMapping>;
  fieldVersionLocks: Record<string, string>; // systemField -> version
  
  // Step 3
  previewEntries: PreviewEntry[];
  validationErrors: ValidationError[];
  
  // Step 4
  classifiedEntries: ClassifiedEntry[];
}
```

### API 변경사항

| API | 변경사항 |
|-----|---------|
| `POST /api/migration/preview` | Request에서 `version` 필드 제거 |
| `POST /api/migration/commit` | Request에서 `version` 필드 제거, actions에 'glossary' 추가 |
