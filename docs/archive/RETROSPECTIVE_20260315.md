## ⚠️ 놓친 점 / 아쉬운 점 (What Could Be Better)

### 1. 사전 에러 탐지 부족
- **문제:** 커밋 후에야 타입 에러 19개 발견
- **원인:** pre-commit hook 미설정
- **영향:** 추가 4-6시간 소요

```
[개선 제안]
husky + lint-staged 설정
→ 커밋 전 자동 타입 체크
→ 사전에 에러 방지
```

### 2. 테스트 커버리지
- **문제:** 32개 테스트 실패 (94.1% 통과율)
- **원인:** 
  - 기존 코드의 누적된 기술 부채
  - 테스트 인프라 부족
- **영향:** PILOT-TEST-001 티켓 추가 생성

```
[개선 제안]
CI에서 테스트 실패 시 알림
→ 테스트 실패 누적 방지
→ 기술 부채 시각화
```

### 3. 자동화 부족
- **문제:** 수동으로 19개 에러 수정
- **원인:** 자동 수정 도구 미활용
- **영향:** 반복 작업, human error 가능성

```
[개선 제안]
AI 기반 자동 수정 도구 검토
→ eslint --fix, prettier 자동화
→ 타입 에러 자동 수정 스크립트
```

### 4. 커뮤니케이션
- **문제:** 사용자가 "GitHub Actions 확인" 의미를 몰랐음
- **원인:** 설명이 기술 중심
- **영향:** 추가 질문 발생

```
[개선 제안]
더 친화적인 설명
→ "CI가 자동으로 테스트 실행 중입니다"
→ 결과 확인 링크 직접 제공
```

### 5. 예상 시간 오차
- **문제:** "4-6시간" 예상 vs 실제 소요 시간
- **원인:** 에러 간 의존성 파악 부족
- **영향:** 일정 관리 어려움

```
[개선 제안]
에러 우선순위 매트릭스
→ 의존성 분석
→ 순차적 예상 시간 산정
```

### 추가 필요한 서브 에이전트

#### 1. **Security Engineer** (보안 전문가)
```
역할:
- 코드 보안 취약점 검토
- 의존성 취약점 체크 (npm audit)
- 보안 정책 수립

필요 이유:
- Pilot Migration은 DB 레벨 변경
- 보안 취약점 사전 예방 필요
```

#### 2. **Performance Engineer** (성능 전문가)
```
역할:
- 성능 벤치마크
- 병목 구간 분석
- 최적화 제안

필요 이유:
- SQLite vs Supabase 성능 비교
- Dark Launch 성능 영향 측정
```

#### 3. **Technical Writer** (문서화 전문가)
```
역할:
- API 문서 자동 생성
- 가이드 문서 품질 검토
- 다국어 지원

필요 이유:
- 6개 문서 생성, 유지보수 필요
- 팀 온보딩 문서화
```

#### 4. **Product Manager** (프로덕트 매니저)
```
역할:
- 우선순위 조정
- 일정 관리
- 이해관계자 커뮤니케이션

필요 이유:
- 7.5시간 예상 작업 일정 조정
- 비즈니스 가치 vs 기술 부채 균형
```

#### 5. **Data Engineer** (데이터 엔지니어)
```
역할:
- 마이그레이션 데이터 검증
- 데이터 정합성 체크
- 롤백 데이터 복구

필요 이유:
- Dual Write 시 데이터 불일치 가능성
- Shadow Mode 결과 비교
```
