- 대상 시스템: **RAG 평가 오케스트레이터** — 사람 1명이 3개 AI(Claude·Kimi·codex)를 지휘해

  **"AI에게 반복 작업을 맡기고 결과를 신뢰할 수 있게 만드는 통제 구조"**에 초점.

## 1. 우수 사례 3선 (효과를 본 것)

### ① 판례집 (append-only) — AI가 같은 실수를 반복하지 않게 하는 장치
**문제**: 세션마다 AI가 새로 시작하니, 지난주에 혼난 실수를 이번 주에 또 한다.
**해법**: 사고가 날 때마다 **판례 문장 1줄 + 사건 요지 + 근거 산출물 + 적용 범위**로 성문화해
파일에 쌓고(정정은 새 항목으로만, 덮어쓰기 금지), 검수 세션마다 프롬프트에 주입.
```
P-001 [발효] 자동 히트는 판정이 아니라 후보다
 - 사건: 공백 제거 매칭의 우연 조합으로 정상 응답을 오탐 기각할 뻔한 사건
 - 적용: 모든 정규식·패턴·분류기 히트 — 기각 판정 전 원문 문맥 확인 의무
```
**효과**: 같은 유형 사고 재발 0. 신규 세션·다른 AI에도 즉시 같은 기준이 적용됨.
→ 제출물: `04_SSOT_문서/판례집_v1_0.md`

### ② 3권 분립 + 트레이(tray) 방식 AI 호출 — 감사 가능한 AI 협업
**문제**: AI가 스스로 만들고 스스로 검수하면 통과율만 높아진다(자기 검수 편향).
**해법**
- **집행(코드) / 감사(독립 세션 AI, 결정권 0) / 결정(사람)** 을 분리. AI는 소견만 낼 수 있고 확정은 사람.
- **AI끼리 직접 대화하지 않는다.** 매 호출은 새 세션이고, 인수인계는 **파일 경유**(트레이에 올려두면 다음 AI가 집어감). 필요한 맥락은 payload에 명시적으로 실어줌.
**효과**: ① 재현성(같은 입력 → 같은 절차) ② 어느 AI가 무엇을 근거로 판단했는지 사후 추적 가능
③ AI 교체가 설정 한 줄(역할별 어댑터)로 끝남.
→ 제출물: `04_SSOT_문서/설계본부_시스템프롬프트_v1_2.md`, `06_구조_참고코드/llm.py`, `sbb_review.py`

### ③ append-only 운영 원장(ledger) — AI 작업의 감사 로그
**문제**: "이 결과가 왜 이렇게 나왔지?"를 사후에 아무도 설명할 수 없다.
**해법**: 모든 AI 호출·판정·승인·반려·사고를 **사유와 실측 수치까지** 한 줄씩 append.
수정·삭제 경로를 코드에 만들지 않음(단일 쓰기 함수).
**효과**: 사고 조사 시간이 "기억 더듬기"에서 "원장 grep"으로 바뀜. 실제로 결함 50건 전수 수리를
이 원장 근거로 진행했음.
→ 제출물: `06_구조_참고코드/olib.py`(ledger_append·상태기계·게이트)

### (부록) 실전에서 효과 본 작은 장치들
| 장치 | 문제 → 해결 |
|---|---|
| **Stop 훅 자동 커밋·푸시** | AI 작업 유실 → 매 턴 종료 시 자동 저장 (10줄, 효과 최대) |
| **체크포인트 재개** | 장시간 작업이 한도로 끊기면 처음부터 → 배치마다 저장, 재실행 시 이어서 |
| **이어달리기** | 한 AI 한도 소진 시 전체 정지 → 다른 AI가 계속, 회복되면 이어받음 |
| **표준 검수 도구** | 매번 즉석 코드로 검사해 결과가 흔들림 → 검사도 도구로 고정(`verify_batch.py`) |
| **SDLC 단계 Skills** | 분석·설계·구현·검증·테스트를 `1-plan`~`5-test`로 표준화 |

## 2. 어려움 3선 (표준이 없어 생긴 비효율)

### ① 개인 전역 설정에 갇힌 자산 — 공유 구조 부재
Skills·판례집·프롬프트가 전부 **개인 계정 전역(`~/.claude/`)** 에 있음. 팀에 넘기려면 수동 복사뿐이고,
누가 최신인지 알 방법이 없음. **연구소 차원의 배포·버전 관리 체계가 없는 것이 가장 큰 병목.**

### ② 다중 AI 구독 운영 노하우가 개인 경험에 머묾
한도 소진의 **오진**이 반복됨. 실측 사례:
- OAuth 토큰 만료가 빈 에러로 와서 "한도 초과"로 오분류 → 무인 워커가 60분 주기로 무의미하게 재시도
- 응답 절단(토큰 한계)을 재시도로만 대응 → 같은 자리 무한 반복 (해결: 배치 이등분 재귀)
- CLI 인수 길이 OS 한계 초과 → 실패 (해결: stdin 폴백)
→ **에러 분류 규칙·재시도 정책의 표준화가 필요.** 팀마다 다시 겪을 문제임.

### ③ AI 산출물의 신뢰 검증을 각자 발명
"AI가 만든 것이 원문에 실재하는가"를 검증하는 방식(문자 대조·근거 필수·환각 탐지)을
프로젝트마다 새로 설계함. 우리도 이 검증 체계를 만드는 데 상당 기간을 썼고,
그 사이 **오탐으로 정상 산출물을 반려한 사고**를 여러 번 겪음(판례집 P-001·P-002가 그 기록).

## 3. 표준 체계 제안 (우리 경험 기반)

1. **판례집 표준 도입** — 연구소 공용 판례집(공통) + 프로젝트 판례집(개별) 2층. 형식·발효 절차 통일.
2. **AI 산출물 3계층 검증 규약** — ① 기계 검증(원문 대조·형식) ② 독립 세션 AI 교차 검토
③ 사람 게이트(결정). 어느 단계에서 무엇을 확인했는지 원장에 남기는 것까지를 규약으로.
3. **운영 원장 스키마 표준** — 최소 필드(시각·단계·행위·주체·사유·근거)를 정해 팀 간 비교 가능하게.
4. **다중 AI 운영 표준** — 에러 분류표(한도/인증/절단/인수한계), 재시도·백오프 정책, 이어달리기,
체크포인트 규격. **이건 우리 코드를 그대로 참조 구현으로 제공 가능.**
5. **Skills·Hooks 사내 레지스트리** — SDLC 단계별 Skill을 사내 표준으로 배포·버전 관리.
6. **비개발자 운영 UX 지침** — AI 자동화를 실제로 굴리는 사람이 기획자·PM인 경우가 많음.
"엑셀 왕복 금지(판단은 도구 안 팝업에서)", "카드에 %와 근거를 함께 표시", "사고와 정책 잠금을
구분 표기" 등 실전에서 도출한 UX 원칙을 표준에 포함할 것을 제안.
