# 신규 판례 추가분 (2026-08-14 ~ 08-21) — 실측 사고 → 구조 수리 6건

> 형식: 사건(실측) → 왜 위험한가 → 구조 수리 → 참고 코드. 전부 실전 운용 중 발생·해결.

## P-014 사람의 반려를 자동화가 무효화하면 안 된다
- **사건**: 사람이 게이트에서 [반려]를 누른 1초 뒤, 자동 진행 루프가 "반려=재검사" 규칙으로
  같은 산출물을 완료 처리하고 다음 단계로 전진 — 반려가 소리 없이 지워짐.
- **수리**: `reject_lock` — 사람이 반려한 단계는 사람이 [다시 시도]를 누르기 전까지 자동 진행 금지.
  회귀 시험 8종으로 고정 (`regression_rejectlock.py`, 격리 실행 ORCH_ROOT).
- **교훈**: 사람 결정은 상태 플래그가 아니라 '잠금'으로 저장해야 자동화가 넘지 못한다.

## P-015 외부 문자열을 추적 파일에 넣는 모든 경로에 검열을 달 것
- **사건**: AI의 실패 응답 원문을 원장(evidence)에 그대로 기록 → 기밀 단어가 자동 커밋으로
  공개 저장소에 유출. 사람 실수가 아니라 '무검열 기록 경로'가 원인.
- **수리**: ① 단일 기록 함수에서 기록 직전 마스킹(금지어 목록은 추적 제외 파일)
  ② Stop 훅 자동 커밋 앞에 기밀 스캔 관문 — 걸리면 해당 경로만 자동 제외+경고.
- **교훈**: 유출 방지는 사람 주의력이 아니라 경로 차단으로.

## P-016 재료(중간 산출물)를 지우는 코드를 두지 말 것
- **사건**: 작업 완주 시 체크포인트를 unlink — 중단된 주자들의 원시 산출물 2.3만 건이 영구 소실
  (스냅샷·git·휴지통 모두 부재 확인). 결과물은 재생산 가능했으나 수고와 교차검증 기회를 잃음.
- **수리**: 삭제 경로 자체를 제거 — '정리'는 보관함 이동+원장 기록으로 대체 (`ckpt_archive`).

## P-017 배치는 개수가 아니라 크기(글자수)로 나눌 것
- **사건**: 청크 25개 고정 배치가 대형 문서 구간에서 1건 60만 자가 됨 — 일부 모델은 입력 초과로
  하드 실패, 일부는 앞부분만 읽고 응답해 "완료로 위장된 부분 커버리지" 발생 (커버율 17.8% 사고).
- **수리**: 글자수 상한 우선 분할 + 응답 절단 시 배치 이등분 → 청크 1개면 본문 이등분(문장 경계).

## P-018 사람이 도메인을 모르는 제품의 채점관 검증 = '구성된 정답지' 방식
- **사건**: 외부사 도메인(일본어) 캘리브레이션에서 사람이 내용 판단 불가 → 일괄 합격 →
  일치율 100%가 무의미해짐 (사람 눈높이 검증이 아니었음을 본인 고지로 확인).
- **수리**: 함정 면접 — 정답을 기계 변조(수치+1, 가부 반전 = 0점이 정답)·의역(합격이 정답)해
  채점관의 판별력·유도리를 도메인 지식 없이 검증 (`trap_calibration.py`, 24/24 통과 후 채용).
- **부수 교훈**: 첫 실행의 '전건 오판'은 시험 도구 결함(변조 답안 미전달)이었음 —
  **채점관을 의심하기 전에 시험지 배달부터 검증하라.**

## P-019 판정 기준서는 단계(태스크)와 결혼시킬 것
- **사건**: 응답 채점용 기준서("응답을 정답과 대조하라")가 문항 품질 판정 단계에 주입 →
  채점관이 "응답이 없으니 0점"이라고 정직하게 오판 — 80건 가짜 불일치.
- **수리**: 기준서에 태스크 모드 조항 명시("입력에 응답이 없으면 문항 판정 모드") + 재판정.
- **교훈**: AI가 이상하게 판정하면 모델보다 먼저 기준서-태스크 정합을 의심.
