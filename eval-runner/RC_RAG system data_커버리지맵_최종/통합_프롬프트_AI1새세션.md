# [작업 지시] RC 커버리지맵 코퍼스판 — 두 트랙 최종 통합

너는 이 작업을 처음 받는 새 세션이다. 이 문서 하나로 배경·규칙·검증·보고 형식을 모두 담았다. 첨부 파일 외의 사전 지식은 필요 없다. 모르는 것은 지어내지 말고 `[확인 필요]`로 표시해 되묻는다.

---

## 0. 이 작업이 무엇인가 (배경)

회사 제품 RemoteCall(RC)의 웹/문서 코퍼스(386문서·3,323청크)를 **RAG 평가용 커버리지맵**으로 분해하는 프로젝트다. 커버리지맵 = "시스템이 아는 사실"을 단위(Unit)로 쪼갠 인벤토리 표.

품질 보증을 위해 **같은 코퍼스를 두 트랙이 독립적으로 분해**했다(상호 비공개, 교차 검증 목적):
- **AI-1 트랙**: 이미 하나의 통합본으로 완성됨 — 779단위 (`통합본_전체` 시트).
- **AI-2 트랙**: 배치별 개별 파일로 확정됨 — 총 2,043단위 (아직 하나로 안 합쳐짐).

네 임무는 이 둘을 **하나의 최종 통합 커버리지맵**으로 합치는 것이다. 두 트랙이 같은 웹을 봤으므로 상당수 단위가 **같은 원문(source)을 가리킨다** — 이걸 병합하고, 한쪽에만 있는 것은 살리고, 어디서 왔는지 출처를 남긴다.

## 1. 입력 (첨부 파일)

**A. AI-1 통합본** (1개 파일)
- `RC_커버리지맵_코퍼스판_통합본_B10_AI1.xlsx`
- `통합본_전체` 시트 사용 (779행). 나머지 시트(제외대장/폴딩대장/근거약함)는 파생물이니 통합 입력에서 제외하고, 최종 단계에서 다시 만든다.
- 컬럼 23개: `# / Unit ID / type / title / description / product / feature / user_type / acl_level / intent / source/resource / source_location / related_units / 이 단위가 말하는 사실 / 답변 가능한 질문 / tags / citation_id / extracted_by / confidence / 상태 / 비고 / doc_key_참고 / 배치`

|---|---|---|

## 2. 통합 규칙 (핵심)

### 2단계로 나눠 진행한다

**STEP 1 — AI-2 트랙 내부 통합 (10파일 → 1시트)**
- 10개 AI-2 파일을 단순 세로 결합(concatenate)한다. 각 행에 `배치`=위 라벨을 채운다.
- AI-2 배치들은 이미 서로 다른 세그먼트라 **트랙 내부에는 원문 중복이 거의 없다** — 그대로 쌓되, 아래 검증에서 source키 중복이 나오면 보고만 하고 임의 삭제하지 말 것.
- 결과: `AI2_트랙통합` 임시 시트 (약 2,043행).

**STEP 2 — 두 트랙 간 통합 (AI-1 779 + AI-2 2,043)**
- **매칭 키 = source키** = (`source/resource` + `source_location`) 두 컬럼의 조합. 이 조합이 같으면 "같은 원문 조각"으로 본다. (문자열 비교 전 반드시 정규화: 앞뒤 공백 제거 + 유니코드 NFC 정규화 + URL 끝 슬래시 `/` 통일.)
- **세 갈래로 분류**:
  1. **양쪽 공통** (source키가 AI-1·AI-2 모두에 존재) → **1개로 병합**. 병합 시 두 단위의 필드를 대조해:
     - 사실·질문·title 등 내용이 실질 동일하면 AI-1 행을 대표로 채택하고, `비고`에 "AI2 동일단위 병합: {AI2 Unit ID}" 기록.
     - 내용이 미묘하게 다르면(한쪽이 더 상세 등) 더 정보량 많은 쪽을 채택하고, 버린 쪽 정보를 `비고`에 요약 보존.
     - `상태`는 더 보수적인 쪽 우선(제외 > 중복 > 근거약함 > 미검토 순으로, 둘 중 더 앞선 것). 상태 충돌은 `비고`에 명기.
  2. **AI-1 단독** (AI-1에만) → 그대로 살림.
  3. **AI-2 단독** (AI-2에만) → 그대로 살림. (이게 교차 검증의 수확 — AI-1이 놓친 것)
- **절대 원칙**: 어떤 단위도 **조용히 사라지면 안 된다**. 병합은 명시 기록과 함께, 삭제는 금지. 최종 통합본 + 병합 로그의 합이 입력 총량과 등식으로 맞아야 한다(§4).

### Unit ID 전역 재부여
- 병합·결합 후 Unit ID가 두 트랙에서 겹치거나 의미가 흐려지므로, **전역 신규 ID를 부여**한다.
  - 형식 유지: `RC-{원천}-{영역}-{일련번호}` (예: `RC-SPEC-MOBILE-001`). 기존 원천·영역 접두는 보존하고, 일련번호만 전역에서 재채번.
  - 제외/폴딩 단위 접두는 `RC-EXCLUDED-*`로 통일(이미 양 트랙 통일됨).
- **기존 ID → 신규 ID 매핑표**를 별도 시트(`ID_매핑`)로 남긴다. (구 AI1 ID, 구 AI2 ID, 신규 ID, 출처트랙)

### related_units 앵커 재해석
- related_units에는 두 형식이 섞여 있다: 실제 Unit ID, 그리고 `영역ID:절명` 형태의 텍스트 앵커.
- ID 재부여 후, related의 **실제 ID 참조는 신규 ID로 전부 교체**한다.
- 텍스트 앵커(`영역ID:절명`)는 신규 ID 체계에서 대표 단위를 찾아 **실제 신규 ID로 해석**한다. 대표가 실존하지 않으면 `[확인 필요]`로 표시(임의 삭제 금지).
- 최종 통합본에 **끊긴 참조 0, 미해석 앵커 0**이 되어야 한다.

### 트랙 출처 태깅
- 컬럼 하나 추가: `출처트랙` = `AI1단독` / `AI2단독` / `공통병합` 중 하나. (교차 검증 증적 — 나중에 "양쪽이 잡은 것 vs 한쪽만"을 필터로 본다.)

## 3. 출력 (파일 1개, 시트 여러 개)

`RC_커버리지맵_코퍼스판_최종통합본.xlsx`, 다음 시트로 구성:

| 시트 | 내용 |
|---|---|
| `최종통합_전체` | 병합·재채번 완료된 전 단위. 컬럼 = AI-1 23컬럼 + `출처트랙` |
| `제외대장` | 상태=제외 전량 (상태 기준, 접두 아님) |
| `폴딩대장` | 상태=중복 전량 |
| `근거약함_담당자확인` | 상태=근거약함 전량 |
| `ID_매핑` | 구 AI1 ID · 구 AI2 ID · 신규 ID · 출처트랙 |
| `병합로그` | 공통병합된 쌍: AI1 ID · AI2 ID · 신규 ID · 병합사유 · 상태채택근거 |
| `통합계리` | §4 등식 결과 표 |

- 대장류 시트는 **상태값 기준으로만** 구성한다(접두 기준 혼용 금지). 검수는 대장-본체 집합 일치(차집합 0)로 한다.

## 4. 완료 보고 (숫자 없는 완료는 반려된다)

반드시 아래를 **실측 숫자**로 보고하라. 말로 "완료"는 인정 안 된다.

1. **입력 검증**: 각 파일 실제 행수 = §1 표와 일치 여부 (11개 파일).
2. **STEP1 등식**: AI-2 10파일 행수 합 = AI2_트랙통합 행수. (예상 2,043)
3. **STEP2 계리 등식**:
   - `공통병합 쌍 수 = C`
   - `AI1 단독 = A1`, `AI2 단독 = A2`
   - **최종 통합본 행수 = C + A1 + A2** (병합은 1행이 되므로 공통은 C로 1회만 계산)
   - **소실 검증 등식**: `AI1 779 + AI2 2043 = 최종 통합본 행수 + C` (공통이 양쪽에서 한 번씩, 총 2C로 입력에 잡혔고 통합본엔 C로 남으므로 차이 C가 병합으로 흡수됨 → 이 등식이 정확히 성립해야 소실 0)
4. **전역 유일성**: 최종 Unit ID 중복 0, 빈값 0, 4단 형식 위반 0.
5. **source키**: 최종 통합본 내 source키 중복 0 (병합이 제대로 됐으면 0이어야 함). 남아 있으면 그 목록 보고.
6. **참조 무결성**: related 끊긴 참조 0, 미해석 텍스트 앵커 0.
7. **대장 정합**: 제외대장 = 본체 상태=제외 수 (차집합 0), 폴딩·근거약함 동일.
8. **출처트랙 분포**: AI1단독 / AI2단독 / 공통병합 각 건수.

각 항목을 표로, 실측값과 함께 제출하라. 하나라도 등식이 안 맞으면 그 원인을 찾아 보고하고 멈춰라(임의 보정 금지).

## 5. 작업 원칙 (반드시 지킬 것)

- **조용한 소실 0**: 병합·재채번 과정에서 단위가 근거 없이 사라지면 안 된다. 모든 삭제·병합은 로그로 남긴다.
- **정규화 필수**: source키 비교 전 공백 제거 + NFC + URL 끝슬래시 통일. (맥에서 만든 파일은 파일명·문자열이 NFD일 수 있으니 `unicodedata.normalize('NFC', ...)` 적용.)
- **임의 판단 금지**: 병합 여부가 애매하거나 대표 앵커가 안 잡히면 `[확인 필요]`로 표시해 남기고, 그 행은 삭제하지 말고 보류 상태로 통합본에 유지한다.
- **완료 보고에 실측 숫자 필수.** 코드로 직접 세어 보고한다.
- 산출·사용자 보고는 한국어, 내부 코드 주석은 영어 무방.

## 6. 첫 응답으로 할 것

1. 첨부 11개 파일을 열어 §4-1 입력 검증(행수 대조)부터 보고.
2. B1 AI-2 확정본이 있는지 먼저 확인 — 없으면 그 사실을 보고하고 멈춰라.
3. 이상 없으면 STEP1 → STEP2 순으로 진행하고, §4 전 항목을 실측 보고.
4. 애매한 병합·앵커는 `[확인 필요]` 목록으로 따로 모아 마지막에 제시.
