# 골든셋 생성 표준 작업 절차 (SOP)

> 버전: v1.5
> 목적: 한 팀의 문서 묶음에서 **RAG 평가용 골든셋**을 일관된 품질로, 누락 없이, 검증 가능하게 만들어내기 위한 재사용 절차.
> 전제 규칙서: 생성 규칙서 v3.4 · 검증 규칙서 v2.4 · 커버리지맵 작업지시서 v0.4 (이 SOP는 세 규칙서를 "어떻게 실행하는가"를 정리한 운영 매뉴얼).
> **v1.5 변경 (DECISIONS DEC-017·018·024·025 반영, 2026-07-08):** ① **상태 표기 규율(DEC-017)** — 생성 AI 산출물의 상태는 "제출·검수 대기"까지만 표기. 합격/확정/승인은 설계본부 판정으로만 부여되는 상태값이다. ② **계획 선승인(DEC-018)** — 배치 통합·분할·순서 변경·후속 단계 착수는 실행 전 사람 승인. 실측 근거가 있어도 사후 통보는 반려 사유. ③ **개정 시 lint 부분수정(DEC-024)** — 규칙 개정 시 기존 확정본은 재생성이 아니라 적합성 점검(lint) → 위반 항목만 부분 수정. ④ **역할 분담(DEC-025)** — 도구·문서 산출물 제작은 작업 AI 몫, 설계본부는 검수만(생성-검증 분리의 도구·문서 확장). 단 규칙서·표준 문서 개정은 검수의 기준 자체이므로 설계본부 소관.
> **상호참조 정정:** 전제 규칙서 생성 규칙서 버전 표기 v3.3 → v3.4 (실제 최신 반영).
> **v1.2 변경 (커버리지맵 작업지시서 v0.4와 동기화):** ① 커버리지맵 상태값을 v0.4 9종으로 통일(`보류` → 미커버/자료부족/근거약함) ② **TC 층화 표본** 처리 — TC는 전수 아님, 완료정의·마일스톤에서 분리 ③ 13컬럼 6번 칸에 `citation_id`(Unit ID) 기계 조인 키 명시(헤더는 13컬럼 유지) ④ acl_level 14번 컬럼 추가(전부 `all`, 권한 도입까지 미사용 자리표시자).
> v1.1 변경: 교차-모델 3세션 검증 파이프라인 명문화 / **1축=스크립트·2축=LLM·확정=사람** 구분 추가 / 발췌 "연속 문자열" 원칙 강화 / 분포에 **F·E 의무 포함, E 15~20% 다이얼** 추가.
> 사용법: `[팀명]`, `[PREFIX]`, `[도메인]` 같은 대괄호 자리표시자를 자기 팀 값으로 바꿔서 사용.

## 0. 한 장 요약 (이 순서대로 한다)

```
입력 모으기 → 문서 인벤토리·버전판정 → (기존 골든셋 점검) → 커버리지 맵 작성
→ [배치 루프: 30문항 생성 → 발췌 근거 달기 → 중복/충돌/사람확인 분리 → 작업보고]
→ 마일스톤 단위 보고 → (별도) 사람·타세션 검증 → 미검토 0 되면 완료
  (★TC는 전수 아닌 층화 표본 — "미검토 0"은 非TC에만 적용, TC는 표본 기준 충족으로 완료)
```

핵심 한 줄: **"자료에 있는 모든 의미 단위를, 자료 글자 그대로의 근거로, 30개씩, 미검토가 0이 될 때까지."**

## 1. 시작 전에 모아야 할 입력 (이게 없으면 시작 불가)

| 입력 | 필수 | 설명 |
|:---|:---:|:---|
| **원본 문서 전체** | ✅ | **RAG 시스템이 실제로 검색하는 지식베이스와 동일한 묶음**이어야 한다. RAG가 못 가져오는 문서로 정답을 만들면 평가가 무의미. 텍스트 추출 가능한 형태(xlsx/pdf/md)가 가장 좋음. |
| **각 문서의 버전·시행일** | ✅ | 현행본 판단·출처 코드 부여에 필수. 어느 문서가 어느 것을 대체하는지 포함. |
| 기존 골든셋 | △ | 있으면 줄 것. 중복 회피 + 스키마 정합 + 병합 기준이 됨. |
| 생성 규칙서 v3.4 | ✅ | 만드는 방법의 표준. (검증 v2.4·judge 프롬프트는 *생성* 단계엔 불필요 — 검증/채점 단계에서 사용) |
| 사용자 질문 로그 | ✕(권장) | 실전 질문 패턴(구어체·실사용)은 자료 밖이라 로그가 있어야 살아남. 없으면 한계로 명시. |

> ⚠️ "필수 문서 종류"는 따로 없다. 필수 = **RAG가 검색하는 원본 묶음 + 각 문서 버전/시행일**. 문서 종류가 다양할수록 더 많은 유형을 검증할 수 있을 뿐.

## 2. 산출물(엑셀) 구조 — 13컬럼 + 6~7시트

### 2.1 본문 시트 (골든셋) — 13컬럼 고정

| # | 컬럼 | 내용 |
|:--:|:---|:---|
| 1 | ID | `[PREFIX]-유형접두어+번호` (예: `[PREFIX]-A01`, `[PREFIX]-G01`, `[PREFIX]-F01`) |
| 2 | 유형 | A~G 중 하나 (§3) |
| 3 | 출제 의도 | 이 문항으로 검증할 능력 1줄 (+ RAG 기법 코드 병기 가능) |
| 4 | 질문 | 실제 사용자가 물어볼 자연어(구어체 허용) |
| 5 | 정답(필수 포함 요소) | 핵심 요소 + 끝에 `/ 필수: …하면 0점` **Knock-out 조건** 명시. 다중정답이면 `[다중정답: 아래 중 하나만 충족하면 정답] ① … ② …` |
| 6 | 근거 출처 | **형식: `citation_id들 ; 사람용 출처 코드들`** (세미콜론 1개로 좌=기계/우=사람 분리, 같은 쪽 다중은 `+`). 좌측 = `citation_id`(=커버리지 Unit ID, 작업지시서 v0.4). 예: `[PREFIX]-SPEC-FUNC-001 ; [PREFIX-SPEC-v1.7]`. 정식 규격은 생성 규칙서 v3.4 §4 형식 규격 박스 |
| 7 | 합격 기준 | 기본 `근거 top-5 내 AND Faithfulness≥4 AND Correctness≥4` + 문항별 필수요소. (F형은 권한등급 위반 시 0점 Knock-out — acl_level 전파 참조) |
| 8 | 난이도 | 상/중/하 |
| 9 | 기대 라우팅 | 문서검색 / DB통계 / 하위질의분할 / 거절 |
| 10 | 검증 상태 | 신규는 `초안` (validate 허용값: `초안`/`검토중`/`검증완료`. 자기검증 금지. "검수 대기"는 11번에) |
| 11 | 작성자/검증자 | 예: `Claude 초안 / (사람) 검수` |
| 12 | **근거 원문 발췌** | **소스에서 글자 그대로** 옮긴 근거. 표는 `행이름 + O/X 값` 그대로. |
| 13 | 신뢰도 | 높음/보통/낮음 (시점민감·해석여지 있으면 낮춤) |
| 14 | acl_level | 접근 권한 등급 = 회사/본부/팀/파트/개인/공개. **현재 전부 `all`**(권한 필터 미도입, 맨 끝 선택 컬럼·미래 대비) |

> ★ **6번 = 커버리지맵 조인 키 (v1.2).** `citation_id`(커버리지 Unit ID)를 기계 키로 적어 커버리지맵↔골든셋을 결정 조인(생성 규칙서 v3.4 §3.1·검증 v2.4 §4.1·§5.1). 사람용 출처 코드는 병기. **칸 내부 형식 = `citation_id들 ; 사람용 출처 코드들`**(세미콜론 1개로 분리, 같은 쪽 다중은 `+`; 정식 규격은 생성 규칙서 v3.4 §4). **헤더는 13컬럼 그대로 유지**(런북 함정 2: 헤더 어긋나면 loader가 못 읽음).
> ★ **acl_level (v1.2 → 14번 컬럼).** 접근 권한 등급(회사/본부/팀/파트/개인/공개)을 단위에서 복사. **맨 끝 선택 컬럼이라 loader가 이름으로 읽어 안 깨지고 `config.yaml`도 무수정**(코드 확인). ⚠️ **현재 권한 필터 미도입 → 전부 `all`, 어떤 채점에도 안 쓰이는 미래 대비 자리표시자.** 권한 도입 시 query-time ACL 입력으로 활성화(그 전까지 F형은 7번 Knock-out 병행).
> ★ **신뢰도(13번) ≠ 커버리지맵 confidence.** 13번 신뢰도(높음/보통/낮음)는 *답변·문항 타당도*, 작업지시서 confidence(상/중/하)는 *단위 추출 충실도* — 측정 축이 다르므로 합치지 말 것(표기만 별개 유지).

### 2.2 부속 시트

| 시트 | 역할 |
|:---|:---|
| **문서 목록(출처 인덱스)** | 문서명·버전/날짜·**출처 코드**·사용여부(사용/보류/제외)·현행본 판단 근거 |
| **커버리지 맵** | 문서를 의미 단위로 분해 → 단위별 상태(v0.4 9종: 미검토/커버됨/미커버/근거약함/자료부족/중복/충돌/사람확인/제외) + 진척률. 단위↔문항 매핑은 citation_id 조인 파생 |
| **충돌 목록** | 출처 간 상반(예: 사양서 O vs 정책 종료) — `주제/출처A/출처B/판정필요/상태` |
| **사람 확인** | AI·스크립트로 못 끝내는 항목(버전 현행성, 방식별 차이, 웹 발췌 불가 등) |
| **작업 보고** | 배치별 추가 내역·유형분포·출처·한계·다음 계획 (누적 append) |
| (검증 결과) | 검증 단계 산출 — 1·2축 결과 |

## 3. 유형 분류 (A~G) + 정답 종류

| 유형 | 정의 | 기대 라우팅 |
|:--:|:---|:---|
| **A** | 단순 문서 조회 — 명시된 사실 그대로 | 문서검색 |
| **B** | 통계/수치 집계 — 개수·평균·비교 (집계 DB 필요) | DB통계 |
| **C** | 복합 — 한 문장에 2개 이상 독립 질문 | 하위질의분할 |
| **D** | 멀티홉 — 단서가 연쇄로 이어져야 답 | 문서검색 |
| **E** | 무응답 함정 — 소스에 **없는** 내용 → 정답="자료에 없음" | 거절 |
| **F** | 권한/거버넌스 — 역할·권한별 가능/불가 | 문서검색 |
| **G** | 경계/예외 — 버전·OS·에디션·플랫폼별 다른 동작의 경계 | 문서검색 |

**정답 종류**: `single`(정답 하나) / `multi`(여러 답이 **모두** 맞음). 어느 게 맞는지 불확실하거나 자료끼리 충돌하면 multi가 아니라 **충돌** → 출제하지 말고 충돌 목록으로.

**분포 기준**(배치 단위 권장): **모든 유형(A·C·D·E·F·G)을 후보에 둔다**(B는 집계 DB 있을 때만). A형 ≤ 60%, C+D 합쳐 ≥ 3, **F(권한/거버넌스)와 E(무응답 함정)를 의도적으로 포함**한다. 난이도 하40/중40/상20 근처. 한 종류로 치우치지 말 것.

> ⚠️ **E 비율은 의도적으로 정하는 다이얼이다.** E(소스에 없는 내용을 묻기)는 환각 저항성을 재는 핵심이므로, 문서-존재 사실(A 위주)만 뽑다 보면 0으로 빠지기 쉽다. 코퍼스 전반에서 **E를 15~20% 수준으로 일부러 끼워 넣을 것.** F도 마찬가지로 "A/C/D/G만" 식으로 빠뜨리지 말 것(권한 매트릭스가 있으면 F는 큰 비중을 차지함).

## 4. 작업 흐름 (배치 루프)

### Step 0 — 환경·자료 추출
- 작업 폴더 준비, 필요한 라이브러리(엑셀·PDF 텍스트 추출) 확인.
- xlsx는 셀 값 그대로, PDF는 텍스트 추출(스캔본/이미지면 "추출 불가"로 따로 처리해 사람확인).

### Step 1 — 문서 인벤토리 + 현행본 판정
- 모든 문서를 **문서 목록 시트**에 등록, 출처 코드 부여.
- **현행본 판정 규칙**:
  - 최신 연도 우선(예: 2026 우선). 이전 연도는 **동등한 최신본이 없을 때만** 보충.
  - 폐지·일회성·예시(`_예시`)·구버전(`~과거연도`, 하위 버전) → **보류 또는 제외**(사유 명시, 애매하면 사람확인).
  - ⚠️ 파일명만 보고 최신이라 단정 금지. 문서 **내부 변경이력/날짜**를 확인(파일명과 내용 버전이 다를 수 있음).

### Step 2 — 기존 골든셋 점검(있으면)
- 스키마가 옛(11컬럼)이면 13컬럼으로 정규화 후 병합.
- 기존이 덮은 의미 단위를 커버리지 맵에 "커버됨(기존)"으로 표시 → **빈 단위만** 신규 생성.
- 기존 문항도 현행 문서와 대조 — 어긋나면 본문에 넣지 말고 충돌/사람확인으로(조용히 버리지 않고 흔적 남김).

### Step 3 — 커버리지 맵 작성 (가장 중요)
- 각 문서를 **의미 단위**로 분해: 시트·섹션·표의 행·조항·절차 단계 등.
- ★ **TC는 전수 아님 — 층화 표본만 단위화**(작업지시서 v0.4 / 생성 v3.2 §1.1). 표본 설계(`TC_표본설계_[PREFIX].md`) 미정이면 TC 보류·사유 기재. 非TC는 전수.
- 단위마다 상태(v0.4 9종): 처음엔 **미검토**, 처리하면 **커버됨**, 의도적 비채움은 사유와 함께 **미커버 / 자료부족 / 근거약함**(기존 단일 `보류` 폐기), 그 외 **중복 / 충돌 / 사람확인 / 제외**.
- 중복 판정은 질문 텍스트가 아니라 **source 키(source/resource + source_location)** 기준(작업지시서 v0.4 §7).
- 이 맵이 종료를 보장한다: 단위는 한 번 처리되면 재등장하지 않으므로 (非TC) 미검토가 0으로 수렴.

### Step 4 — 배치 생성 (30문항씩)
- **30개 단위**로 생성(오류율 관리). 빈 단위만 채움.
- 비어 있는 유형부터 우선(보통 처음엔 G/F/C/D가 비어 있음).
- 분포 기준(§3) 지킴.

### Step 5 — 근거 원문 발췌 (절대 원칙)
- 정답의 근거가 되는 문장은 **소스에 글자 그대로 존재**해야 함. 추측·요약·창작 금지.
- 표(O/X 매트릭스 등)는 **컬럼 의미 + 행이름 + 값**을 발췌칸에 그대로. 컬럼 매핑 설명은 정답칸에.
- 파일명/제목으로 추정 금지.

### Step 6 — 중복·충돌·사람확인 분리
- 신규 ID가 기존과 겹치지 않는지, 주제가 기존 문항과 중복되지 않는지 점검.
- 출처 간 상반 → **충돌 목록**(multi 아님).
- 버전 현행성·방식별 차이·웹 발췌 불가 등 → **사람 확인**.

### Step 7 — 작업 보고 + 진척률
- 배치별로 추가 수·유형분포·출처·한계·다음 계획을 작업 보고에 누적.
- 커버리지 맵에 진척률 갱신: `처리(커버됨 + 의도적 비채움) / 전체 = N%`. (의도적 비채움 = 사유 달린 미커버/자료부족/근거약함. TC 표본탈락 단위는 분모에서 "표본 설계 제외"로 별도 표기 — 검증 v2.4 §4.5)

### Step 8 — 검증은 별도 단계 (자기검증 금지) · 교차-모델 파이프라인

자기검증 금지(검증 v2.4 §9)의 권장 구현 = **생성·검증·확정 주체를 3개로 분리**:

1. **[세션 1] 생성 — 모델 A (예: Claude).** RAG 문서 + 생성 규칙서 v3.4(+draft 프롬프트) → 30문항 초안(JSON/표). 전부 검증 상태 `초안`(작성자/검증자 칸에 "(모델) 초안 / (사람) 검수").
2. **[세션 2] 검증 — *다른 모델* B (예: GPT Pro).** 같은 RAG 문서 + 검증 규칙서 v2.4(+judge 프롬프트) + 모델 A의 산출물 → 채점. **생성·검증을 다른 모델로 분리하면 상관된 환각(공통 맹점)을 줄인다.**
   - **1축 = 발췌 문자대조 → 스크립트(결정적)로 한다.** 원문에 발췌 문자열이 그대로 있는지는 정확한 부분일치 검사이고, *어떤 LLM도 이 일에는 부정확*하다(근사일치를 "맞다"고 통과시킴). 스크립트가 더 신뢰도 높음. LLM은 1축 보조로만.
   - **2축 = 정답 타당성/날조 여부 → LLM 판단(모델 B).** 발췌를 넘어선 창작·과장·Knock-out 위반 여부 등 *판단*이 필요한 부분에서 LLM-judge가 가치를 더한다.
3. **[세션 3] 확정 — 사람(기획자).** 통과 문항만 **마스터에 누적**(권장: 검증 통과 전 초안은 마스터에 'draft' 표시로만 적재하고, 통과 시 'ship'으로 승격). '반려/의심'은 사람이 육안 확인해 교정 또는 폐기(삭제 필요/사람 확인 시트).

> 핵심: **1축은 스크립트, 2축은 (다른 모델) LLM, 최종은 사람.** 생성한 모델이 자기 것을 1·2축 판정하지 않는다.

### 반복
- Step 4~7을 **마일스톤(문서 묶음) 단위**로 반복. 한 마일스톤 끝나면 멈춰 보고 → 다음.

## 5. 절대 원칙 (위반 시 그 문항 폐기)

1. **자료에 실제로 있는 내용만** 출제. 없는 기능·수치·정책 창작 금지.
2. **발췌는 원문의 "연속된 문자열" 그대로.** 요약·창작뿐 아니라 **`...`/`…` 삽입, ` | ` 같은 구분자 재배치, 약어화도 금지** — 1축(문자대조)은 결정적 부분일치 검사라, 표기를 재구성하면 통과하지 못한다. **표(O/X 매트릭스)는 "행이름"과 "각 셀 값"을 분리해 원문 토큰 그대로 적되, 컬럼 매핑 해석은 정답칸에만** 쓴다. (실측 결과, 매뉴얼 직접 인용은 1축 통과하지만 `...`·재구성된 사양서 발췌는 불통과함 — 이 규칙을 어기면 검수에서 대량 반려된다.)
3. **파일명·제목으로 추정 금지.** 내용을 읽고 그 안에서만.
4. **현행본이 authoritative.** 구버전 발췌 금지. 버전 충돌은 충돌 목록.
5. **억지 생성 금지.** 소재가 약하면 의도적 비채움(미커버/자료부족/근거약함)으로 사유 명시. 단, **미검토 ≠ 의도적 비채움** — 안 열어본(상태 `미검토`) 단위는 비채움이 아니라 누락이다.
6. **충돌을 multi로 내지 말 것.** "둘 다 진짜 맞나?"에 확신 없으면 multi 아님.
7. **B형(통계)은 집계 DB가 없으면 PASS**(생성 불가로 보고). 자료 확보 시 활성화.
8. **자기검증 금지.** 생성과 검증의 주체 분리.
9. **민감·해석여지·시점민감**(예: "최신 N개 버전") 문항은 신뢰도를 낮추고 사람확인 권장.

## 6. "어떤 문서가 어떤 유형을 낳는가" (소재 매핑)

| 가진 문서 | 잘 나오는 유형 | 없으면 |
|:---|:---|:---|
| 규정·정책(제N조/항) | A, F(권한), 충돌 검사 | 권한·거버넌스 PASS |
| 사양서·에디션/OS 매트릭스 | A, G(경계), 계층 결합 | 경계 테스트 PASS |
| 매뉴얼·절차 가이드 | A, C(복합), D(멀티홉) | 절차/멀티홉 소재 부족 |
| FAQ·헬프데스크 | A, 구어체 매칭 | 실전 표현 약함 |
| 권한별로 다른 문서/권한 매트릭스 | F, 권한 필터링 | 권한 테스트 PASS |
| 집계 가능한 통계 DB | B(통계) | B형 자체 PASS |
| OS·브라우저·버전 사양 | G(경계·예외) | 버전 경계 약함 |
| TestCase(TC)·체크리스트 | A·G·F(검증 조건·기대 결과) ★층화 표본만 | 표본 설계 없으면 보류 |
| KnownIssue | A·D(이슈·조건·조치), 충돌 검사 | 이슈 추적 약함 |

> 문서가 다양할수록 검증 가능한 RAG 기능이 늘고, 한쪽으로 치우치면 그만큼 PASS(해당 없음)가 늘어난다.

## 7. 진척·종료 정의 ("언제 끝나는가")

- **끝의 정의**: 모든 문서의 모든 의미 단위가 **"커버됨" 또는 "사유 달린 비채움(미커버/자료부족/근거약함)"**이 되고, **"미검토"가 0**일 때. ★단, 이는 **非TC** 기준. TC는 표본이라 전수 미검토 0이 아니라 **표본 설계 기준 충족**으로 완료를 판정한다.
- **진척 신호**: 매 단계 끝에 `처리/전체 = N%`를 보고. 0을 향해 줄어드는 게 보임. (TC 표본탈락 단위는 분모에서 "표본 설계 제외"로 별도 표기)
- **마일스톤**: 문서 묶음 단위로 결승선(예: ① 사양서 완주 → ② 매뉴얼 완주 → ③ Known Issue → ④ TC(표본) → ⑤ FAQ/헬프데스크). 단계마다 멈춰 보고.
- **완료 선언**: (非TC) 미검토 0 + 남은 게 정당한 비채움뿐 + TC 표본 기준 충족일 때 명시적으로 "완료" 선언.

## 8. 운영 메모 (실제로 이렇게 돌렸다)

- **배치 = 30문항**. 한 세션에서 여러 배치를 이어서 돌릴 수 있음(중간 승인 불필요). 단, 한 번에 전체 코퍼스를 끝내는 건 분량상 불가 → 여러 세션에 걸쳐 진행하고 매 세션 진척 보고.
- **출력 파일은 버전업**(예: `..._v1_8 → _v1_9`)으로 누적. 골든셋 버전은 소스 문서 버전과 별개 라인.
- **셀 색 구분**(선택): G=경계 주황, F=권한 초록, C/D=복합/멀티홉 파랑 — 검수 가독성↑.
- **중복 방지**: 기존이 "기능 가부(WHAT)"를 덮었다면, 매뉴얼은 "절차(HOW)"로 출제축을 달리해 중복을 피함.

## ★ 표준 변경 관리 (v1.3 신설)

1. **5종 일괄 갱신 원칙** — 스키마·컬럼·유형 정의·상태값을 바꿀 때는 다음 5종을 **한 번에** 갱신하고 버전을 맞춘다: 생성 규칙서 · SOP · 런북 · 검증 규칙서 · judge 프롬프트. (v3.3 개정의 배경: 검증 라인만 answer_type으로 진화하고 생성 라인이 남아 2제품에서 같은 누락이 재발했다.)
2. **변경 건수 보고 의무** — 생성·수정 작업의 완료 보고에는 **항목별 변경 건수를 숫자로** 명시한다(예: "E형 197→52건, A형 이동 89건"). 숫자 없는 "수정 완료" 보고는 접수하지 않는다. (허위 완료 보고 4건 실측에 따른 조치)
3. **등식 검수 원칙 (v1.4 신설)** — 수정본 검수는 근사치가 아니라 **등식**으로 한다: `총 행수 = 기존 행수 + 신규 건수 − 삭제 건수`. 1이라도 어긋나면 무단 추가/삭제 신호로 **반려**. 비율 기준(예: E형 15~20%)의 분모는 **최종 총 문항수**로 통일한다.
4. **judge 캘리브레이션 관문 (v1.4 신설)** — 제품 최초 2축 착수 전, 사람 확정 완료분 기반 **정상 15 + 의도적 오염 15 = 30건** 스모크 테스트로 judge 일치율을 측정한다. **일치율 ≥90% 통과**, 미만이면 judge 프롬프트 수정 후 재측정. (표본 30은 ±15%p 오차 — 스모크로 취급, 결과는 숫자로 기록)
