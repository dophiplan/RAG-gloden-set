# STAGE ① 생성 (골든셋 질문 만들기)

## Step 1. [너] 입력 모으기
- 원본 권위 문서 **본문(텍스트)** — *알피스 RAG가 검색할 묶음과 동일하게.* (⚠️ 링크만 ❌ → 모델이 본문을 못 보면 발췌를 지어냄. 본문을 줘야 함)
- 각 문서 버전·시행일, 현행본만 남기고 구버전·예시는 가림

## Step 2. [AI에 시킴] 커버리지 맵 만들기
문서를 "사실 체크리스트(Layer 1 표)"로 쪼개는 단계. 아래 프롬프트를 그대로 쓴다.
※ 이 표가 커버리지맵 작업지시서 v0.4의 **Layer 1**이다. OKF `.md` 번들(Layer 2)은 위키 서빙이 필요할 때만 별도로 만든다(작업지시서 8장) — 여기선 만들지 않는다.

```
너는 문서를 빠짐없이 분해하는 작업자야.
너는 커버리지맵을 만드는 데 1인자야.

아래 [문서]를 "의미 단위(커버리지 단위)"로 전부 쪼개서 커버리지맵 표(Layer 1)를 만들어.

[의미 단위 정의]
의미 단위 = 질문 하나로 답할 수 있는 최소 덩어리

* 규정·정책 → 조/항 단위
* 사양서·표 → 표의 행 하나하나
* 매뉴얼·가이드 → 절/소제목 단위
* TestCase(TC) → ★전수 아님★. 별도 [TC 표본 설계]에 따라 표본 항목만 단위화 (아래 참조)
* KnownIssue → 이슈/발생조건/영향/조치 단위 (전수)
* FAQ/Helpdesk → 질문·답변 항목 단위
* 표는 절대 요약하지 말고 행을 하나씩 분해
* 한 덩어리에 사실이 여러 개면 쪼갬
* 여러 행이 합쳐져야만 답이 되는 경우에만 묶음

[★ TC 예외 — 전수 분해 금지]
* TC는 분량이 압도적이라 전수 분해하지 않는다. [TC 표본 설계] 문서의 (a)기능군 (b)우선순위 (c)유형별 비율 (d)그룹별 표본 수에 따라 표본만 단위화한다.
* TC 표본 파라미터가 아직 미정이면 TC 단위화는 보류하고 그 사유를 비고에 적는다.
* TC를 뺀 나머지(사양서·매뉴얼·KnownIssue·FAQ·Helpdesk)는 원문 대비 1:1 근접 전수.

[사용할 원본]
* RC_RAG_AI_file 폴더의 파일을 우선 사용한다.
* 구버전, 최신본과 중복되는 파일, 기존 골든셋 산출물, 타제품 자료는 분해하지 않는다(비고에 사유).
* Helpdesk 링크는 웹 출처로 별도 취급한다(파일 출처와 구분).

[메타데이터 규칙 — 각 단위마다 반드시]
1. Unit ID: {PREFIX}-{원천}-{영역}-{번호}. 예: RC-HELP-SEC-001 (표의 행 식별자)
2. type: Manual / Spec / TestCase / KnownIssue / HelpdeskArticle
3. title: 원본 문서 제목
4. product: RemoteCall
5. acl_level: 접근 권한 등급 = 회사/본부/팀/파트/개인/공개 (★거버넌스. 표시 없으면 기본 '회사', Helpdesk 공개문서는 '공개'. user_type=독자역할과 혼동 금지)
6. source/resource: 파일 경로 또는 URL
7. source_location: 원문 내 위치 — ★단위가 유일하게 식별되는 입도까지★ 적는다. 'p.12'❌ → 'p.12 / 표2 / 3행'⭕ (안 그러면 dedup이 쪼갠 단위를 도로 합침)
8. related_units: 연결되는 다른 Unit ID(있으면). 예: TC↔검증대상 Spec, KnownIssue↔발생 절차. 여러 개면 ';'. 없으면 빈칸
9. tags: 제품명·기능명·화면명·보안/관리자/연결/오류 등 검색 키워드
10. citation_id: 골든셋이 이 단위를 근거로 지목할 조인 키. ★커버리지맵에선 Unit ID와 동일★
11. extracted_by: 생성 모델/작업자 (예: claude-opus)
12. confidence: 추출 충실도 = 상/중/하 (원문을 얼마나 충실히 담았나. 숫자 아님)

[출력 형식 — 표]
| # | Unit ID | type | title | product | acl_level | source/resource | source_location | related_units | 이 단위가 말하는 사실 | 답변 가능한 질문(대표 1개) | tags | citation_id | extracted_by | confidence | 상태 |
| - | ------- | ---- | ----- | ------- | --------- | --------------- | --------------- | ------------- | --------------------- | -------------------------- | ---- | ----------- | ------------ | ---------- | --- |
| 1 | RC-HELP-SEC-001 | HelpdeskArticle | RemoteCall 2단계 인증 사용 방법 | RemoteCall | 공개 | URL | 본문 2단계 / 설정 위치 | RC-MANUAL-ADMIN-007 | 관리자페이지 사용자 관리 > 회사에서 2단계 인증 사용을 체크한다 | RemoteCall 2단계 인증은 어디에서 설정하나요? | RemoteCall, 보안, 2단계인증, 관리자페이지 | RC-HELP-SEC-001 | claude-opus | 상 | 미검토 |

[상태값 — 9종 중 하나]
처음 생성 시 상태는 모두 "미검토". 단, 분해 중 사유가 명확하면 즉시:
미검토 / 커버됨 / 미커버 / 근거약함 / 자료부족 / 중복 / 충돌 / 사람확인 / 제외
(★ 기존 '보류'는 쓰지 말 것 → 사유에 따라 미커버/자료부족/근거약함으로 적는다)

[주의사항]
* 전수 대상은 중요한 것만 고르지 말고 처음부터 끝까지 전부 분해. (단, TC는 표본)
* 표는 요약하지 말고 모든 행을 하나씩.
* (source/resource + source_location)이 단위마다 유일해야 한다.
* 이미지 설명만 있고 텍스트 근거 부족 → 상태 "사람확인".
* 구버전/중복/산출물/타제품 → 분해 말고 비고에 기록.
```

**▶ 끝나면 [너]가 할 일 (중요):** 나온 맵을 **원본 문서 목차랑 대조.** "모든 조/표 행/소제목이 맵에 한 줄씩 있나?" (단 TC는 표본 설계 기준 충족 여부로 본다)

## Step 3. [AI에 시킴] 단위마다 질문 + 발췌
입력 = **이 프롬프트 + 커버리지 맵(미검토 단위) + 원본 문서 본문** (옵션: 생성 규칙서 v3.4)

```
너는 RAG 평가용 골든셋 출제자야.
아래 [커버리지 맵]의 '미검토' 단위마다, [원본 문서]를 근거로 문항을 1개씩 만들어.

[절대 원칙 — 어기면 그 문항 폐기]
1. 원본에 실제로 있는 내용만. 없는 사실·수치 지어내지 마.
2. ★발췌는 원문에서 글자 그대로 복사★ (다시 쓰는 게 아님).
   요약·말줄임(...)·순서 바꾸기 금지. 연속된 문장 그대로.
3. 질문은 실제 사용자가 물어볼 자연스러운 말로.
4. 자료끼리 다르면(충돌) 만들지 말고 따로 표시.
5. ★질문 유일성★ — 질문만 읽고 어느 단위를 묻는지 특정되게(실제 기능명·플랫폼·버전 포함). 동일 질문 텍스트 중복 금지.
6. 원천 셀이 비어 있으면 그 값을 정답에 넣지 마라 → 그 문항 보류(사람확인).
7. E형은 자료 어디에도 정보가 ★존재하지 않을 때만★. "미지원/X"가 명시돼 있으면 E가 아니라 A/G형(근거 있는 사실). E형 발췌 칸은 공란.

[각 문항에 적을 것]
- 유형: A(단순조회) B(통계) C(복합) D(멀티홉) E(무응답함정) F(권한) G(경계)
- 질문
- 정답(필수 포함 요소) + 끝에 "/ 필수: ~틀리면 0점"
- 근거 원문 발췌 ← 답의 근거 문장을 원문에서 그대로 복사
- citation_id ← ★그 단위의 Unit ID를 그대로 적는다★ (커버리지맵과 골든셋을 잇는 조인 키)
- 출처: 그 단위의 source/resource + source_location (사람용 출처 코드 병기 가능)
- acl_level ← ★`all` 고정★ (권한 체계 미도입 표식 — 생성 규칙서 v3.4 §3.1 14번). 그 단위의 acl 값은 `acl_참고` 컬럼에 보존 (F형 채점 시 query-time ACL은 acl_참고를 씀)
- answer_type ← `single`(정답 하나) / `multi_equivalent`(여러 답 모두 정답 — 각 답에 근거 필수). 확신 없으면 single + 비고
- 난이도: 상/중/하
- 검증 상태: 초안

[규칙] 한 번에 30단위까지. 한 단위 = 한 문항. 만든 단위는 표시.
[출력] 표로.

[커버리지 맵]
(미검토 단위들 붙여넣기)
[원본 문서]
(문서 본문 붙여넣기)
```

- **발췌 = 원문에서 `Ctrl+C` 해오는 문장.** (지어내기 ❌ — 나중에 verifier가 `Ctrl+F`로 확인)
- 분포 챙기기: A형 ≤60%, F(권한)·E(무응답함정) 의무 포함, E는 15~20%
- 단위 상태는 citation_id join으로 파생: 문항이 그 Unit ID를 인용하면 `커버됨`, 아직 문항이 없으면 `미커버`. (손으로 `미검토→커버됨` 토글하면 골든셋이 커질 때 stale되므로, 가능하면 join으로 계산)

## Step 4. [너] 충돌 / 사람확인 분리
- 출처끼리 답이 다름(둘 중 하나만 맞음) → **충돌 목록** (multi 아님)
- 버전·방식·웹발췌 불가 → **사람 확인 시트**

## Step 5. 반복 → 미검토 0
- Step 3~4를 문서 묶음 단위로 반복. 커버리지 맵 `미검토`가 0이면 생성 끝 = **골든셋 초안 완성.**
- ★ **TC 예외:** TC 단위는 전수가 아니라 표본이므로, TC는 "표본 설계 기준을 채웠나"로 완료를 판정한다(전수 `미검토 0` 적용 대상 아님). 非TC만 `미검토 0`을 적용.

## (옵션) 꼼꼼 버전 — 모델별 골든셋 합치기
3모델로 각각 만들었으면 "그냥 합쳐줘" ❌. 이 프롬프트로:

```
아래 [골든셋 3개]를 [커버리지 맵] 기준으로 하나로 합쳐.

[규칙]
1. 커버리지 맵의 '단위'별로 문항을 묶어. ★묶음 기준은 단위의 citation_id(=Unit ID), 그게 없으면 source 키(source/resource + source_location)다. 질문 텍스트가 비슷하다고 묶지 마.★
2. 같은 단위에 문항이 여러 개면 → 하나만 남겨. 우선순위:
   ① 발췌가 원문에 그대로 있는 것(verifier '완료') ② confidence(추출 충실도)가 높은 것 ③ 질문이 더 자연스러운 것.
   나머지 중복은 버려.
3. 한 모델만 만든 단위도 버리지 말고 살려(합집합).
4. ★같은 단위인데 모델들이 '답 내용'이 다르면(표현 차이 말고 사실이 다름)
   임의로 고르지 말고 '충돌'로 따로 빼. (내가 볼 거야)
5. ID 다시 매겨. (단, citation_id=Unit ID는 유지 — 커버리지맵 조인이 끊기지 않게)

[출력] 합쳐진 골든셋 표 + 따로 '충돌' 표.
[커버리지 맵] (붙여넣기)
[골든셋 3개] (붙여넣기)
```
> 팁: verifier를 3번 따로 말고 **합치고 나서 한 번**.
