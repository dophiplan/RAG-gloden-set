# DECISIONS.md — 판례집

> 막혔다가 **풀린** 것들의 기록. 판정과 그 근거를 남겨, 같은 상황이 또 오면 일관되게 처리한다.
> 반복될 패턴이면 `헌법승격` 칸에 표시하고 `CONSTITUTION.md`에 조항으로 올린다.
>
> 작성 규칙: 각 항목에 **발생노드 · 이슈유형**을 단다(OPEN_ISSUES와 동일 카테고리). 그래야 판례도 묶어 셀 수 있다.

---

## 작성 형식

- **ID**: `DEC-{번호}`
- **출처**: 어디서 왔나 (ISS-xxx 또는 직접 발생)
- **발생노드 / 이슈유형**: OPEN_ISSUES와 같은 태그
- **상황**: 무엇이 문제였나
- **판정**: 어떻게 결정했나
- **근거**: 왜 그렇게 판정했나
- **헌법승격**: 예(→ §조항) / 아니오(단발)

## 판례

### DEC-001 — completed=0을 환각으로 오판하지 않는다
- 출처: RM 1축 결과 검토 (직접 발생)
- 발생노드: 1축 / 이슈유형: `소스미발견`(오판)
- 상황: 1축에서 완료 0 / 미정 112 / 탈락 18이 나와 "전부 환각인가?" 의심.
- 판정: 환각 아님. 대부분 발췌가 원문에 실재하나 출처(citation) 미인용으로 `ok_uncited` 처리된 것.
- 근거: "완료"는 발췌 진위 + 출처 일치를 동시에 요구. 출처를 채우면 완료로 전환됨. found_in에 원문 파일이 채워져 있었음.
- 헌법승격: **예 → §3.1**

### DEC-002 — missing은 원문 대조 후에만 완료로 (일괄 완료 금지)
- 출처: 사용자가 탈락 18건을 일괄 완료로 바꾼 시도 (직접 발생)
- 발생노드: 확정 / 이슈유형: `소스미발견`
- 상황: missing 18건을 사람이 한 번에 "완료"로 변경하려 함.
- 판정: 금지. 각 건을 원문에서 실제로 찾아, 있으면 발췌 교정 후 완료 / 없으면 탈락.
- 근거: missing을 무판정 완료로 올리면 진짜 환각이 검증완료로 위장됨. "사실로 맞다"≠"발췌가 원문에 있다".
- 헌법승격: **예 → §3.2**

### DEC-003 — 한글 PDF 줄바꿈은 공백무시 재시도로 구제
- 출처: RM 1축에서 38건 억울한 탈락 (직접 발생)
- 발생노드: 1축 / 이슈유형: `소스미발견`(추출 정규화)
- 상황: pdftotext가 단어 중간에 줄바꿈을 끼워(`로그\n인`) 멀쩡한 발췌가 missing/partial로 떨어짐.
- 판정: verifier를 strict(공백1칸) 우선 → 실패 시 공백 완전무시 재시도로 수정. (text.py·corpus.py)
- 근거: strict 우선이라 기존 통과분 회귀 없음, 환각(지어낸 문장)은 여전히 미발견. 테스트로 3가지(구제·회귀없음·거짓통과없음) 확인.
- 헌법승격: **예 → §3.3**

### DEC-004 — 다중정답을 충돌로 오판하지 않게 judge 분기
- 출처: 2축 judge 프롬프트 검수 (직접 발생)
- 발생노드: 2축 / 이슈유형: `스키마구멍`+판정기준
- 상황: 표준 judge 6번이 "정답이 한 가지로 수렴?"이라 multi_equivalent를 오탐할 위험.
- 판정: 6번을 answer_type별로 분기. multi는 "목록 중 하나로 답해도 정답이면 통과", "다중정답≠충돌" ★★가드 추가. answer_type을 입력에 추가(없으면 single).
- 근거: 검증규칙서 §3.3. RAG는 다중정답 흔함. 4제품 표준 키트가 될 것이라 미리 보강.
- 헌법승격: **예 → §3.4** (스키마 컬럼 추가는 ISS-006로 별도 추적)

### DEC-005 — errdef에 없어도 현행화 PDF에 있으면 타당 (소스 위계)
- 출처: RM 에러코드 6건(EA03·EA09·EA10·EA11·NA11·F01 일부) (직접 발생)
- 발생노드: 2축 / 이슈유형: `코드드리프트`+소스위계
- 상황: errdef 정의문서에 없는 코드들 → "환각인가?" 의심.
- 판정: errdef는 일부 레거시 코드를 안 담았을 뿐, 현행화 PDF error표에 실재 → 현행화 소스로 grounding하여 타당화. 탈락 0.
- 근거: "사전에 없음"≠"원문에 없음". 발췌가 다른 소스에 verbatim 실재하면 환각 아님.
- 헌법승격: **예 → §3.5**

### DEC-006 — 코드 정본은 5자리(40xxx/30xxx)로 정규화
- 출처: RM 에러코드 드리프트 (직접 발생)
- 발생노드: 생성/2축 / 이슈유형: `코드드리프트`
- 상황: 같은 오류의 코드가 `0223`↔`40223`, `0117`↔`40117`↔`40502` 등으로 어긋남.
- 판정: errdef 체계가 5자리 정본이므로 그 기준으로 정규화. citation은 정본 코드로 통일.
- 근거: ID가 흔들리면 영향분석·역추적이 무너짐. 단일 정본 코드 필요.
- 헌법승격: **예 → §3.6**

### DEC-007 — F형 권한: 근거에 권한 주체 실재 여부로 3분기
- 출처: RM F형 권한 24문항 (직접 발생)
- 발생노드: 생성(결함) / 이슈유형: `권한근거없음`
- 상황: 정답이 "그룹 관리자"인데 근거에 권한 주체가 있는지 코드마다 달랐음. Kimi 판정도 근거와 불일치.
- 판정: 소스 대조로 3갈래 — 권한주체 있음(발췌 확장→타당) / 없음(정답서 권한조항 삭제) / 미발견(사람확인).
- 근거: 정답의 Knock-out(권한)은 근거에 실재해야 타당. 순수 기술/결제 오류엔 권한 조항 근거 없음.
- 헌법승격: **예 → §3.7** (단, 24건 쌓인 것 자체가 생성 노드 결함 신호 → 트리아지 대상)

### DEC-008 — NA 번호는 재번호하지 않는다
- 출처: RM NA01 시퀀스 의심 (직접 발생)
- 발생노드: 생성 / 이슈유형: (시퀀스 — 누락 아님)
- 상황: NA가 02부터 시작 → NA01 누락 의심.
- 판정: 누락 아님. 신규 에러 11개가 번호를 나눠 가져 NA01 자리를 NF01이 차지한 것. 재번호 금지.
- 근거: 재번호하면 citation_id 연결이 전부 흔들림.
- 헌법승격: **예 → §3.8**

### DEC-009 — 마케팅 홍보문은 억지 문항화 금지, 사유 미커버
- 출처: RM 헬프데스크 마케팅 ~45건 (직접 발생)
- 발생노드: 생성 / 이슈유형: `발췌불가`(저사실밀도)
- 상황: 헬프데스크 162 article 중 마케팅 순수 홍보문을 문항화할지.
- 판정: 사실 있는 article(~90)만 분해, 마케팅은 "저사실밀도 — 마케팅 홍보문"으로 사유 미커버.
- 근거: 세일즈 문구는 정답 있는 질문이 안 나옴. 억지 문항화는 평가셋 오염.
- 헌법승격: **예 → §2.8**

### DEC-010 — 검증 후 처리는 status별 4갈래 (전수 사람검수 아님)
- 출처: RM 1축 후처리 (직접 발생)
- 발생노드: 1축 후처리 / 이슈유형: (운영 효율)
- 상황: 130건을 사람이 다 봐야 하나?
- 판정: 아니오. e_trap→일괄 통과 / ok_uncited→출처 채워 완료 / partial→사람 소수 확인 / missing→원문대조. 사람은 partial+애매만.
- 근거: status별로 자동/반자동/사람이 갈림. 전수 사람검수는 비효율.
- 헌법승격: 아니오(운영 절차 — SYSTEM.md/에이전트에 반영)

### DEC-011 — E형 부재 기준은 정본, 코퍼스 결손은 인입 누락 리포트로
- 출처: 실물 RAG 연결 논의 + 외부 AI 교차검토 (2026-07-07)
- 발생노드: 생성/설계 / 이슈유형: `시스템 종속 위험`
- 상황: "RAG 학습 데이터 기준으로 골든셋 재구성" 결정이 E형을 코퍼스 종속으로 만들 위험(코퍼스 갱신 때마다 정답 뒤집힘 = 시험지 고정 불가).
- 판정: E형 기준은 **정본 문서에 없음** 유지. 코퍼스 export는 범위·원문 확보 경로로만. 출제 시 정본+코퍼스 이중 부재 확인(코퍼스 대조=1차 필터, 최종=2축). 코퍼스에만 없는 것은 E형 금지 → **인입 누락 리포트** 별도 산출. 코퍼스 버전은 성적표 메타데이터.
- 근거: 원칙 7(시스템 비종속) 정합. E1/E2 유형 분리안은 종속성을 스키마에 제도화하므로 기각(검토자 본인 철회).
- 헌법승격: 아니오(생성규칙서 v3.4 §3.2·방법론 v1.2 §2 반영)

### DEC-012 — 수정본 검수는 등식으로 (근사치 금지)
- 출처: RC v3 합격선 분모 모호 지적 (외부 교차검토)
- 발생노드: 검수 / 이슈유형: `판정 불능`
- 상황: "E형 ~15%"가 분모(1,242 vs 1,428)에 따라 합격/불합격이 갈림. "약 186건" 지시도 분모 오류(정답은 220~310).
- 판정: 검수는 **등식**으로 — 총 행수 = 기존 + 신규 − 삭제 (1 어긋나도 반려). 비율의 분모는 최종 총 문항수.
- 근거: 허위 보고 4회 전력 프로세스에선 등식이 근사치보다 강함.
- 헌법승격: 아니오(SOP v1.4 §3 반영)

### DEC-013 — judge 캘리브레이션 관문 (2축 착수 전)
- 출처: "채점기 신뢰도 미검증" 지적 (외부 교차검토)
- 발생노드: 2축 / 이슈유형: `채점기 신뢰도`
- 상황: judge와 사람 판정의 일치율을 한 번도 측정 안 함 — 채점기가 틀리면 "환각 0" 결론 전체가 흔들림.
- 판정: 제품 최초 2축 전 관문 — 사람확정분 기반 정상 15+오염 15=30건 스모크, **일치율 ≥90% 통과**, 미만이면 judge 프롬프트 수정 후 재측정. 2축은 가급적 타 벤더 모델(기존 런북 6-2 유지).
- 근거: false-pass·false-fail 양쪽 측정. 표본 30=±15%p 오차라 스모크로 취급.
- 헌법승격: 아니오(SOP v1.4 §4·런북 v3.3 §6-1.5 반영)

### DEC-014 — 정본에 있으나 코퍼스에 없는 문항: 시험지에 포함
- 출처: 실물 RAG 연결 설계 (사용자 확정 2026-07-07)
- 발생노드: 설계 / 이슈유형: `범위 결정`
- 상황: 정본 문서엔 있는데 실물 RAG 코퍼스에 인입 안 된 내용의 문항을 시험지에 넣는가.
- 판정: **포함한다.** 그 문항의 실패는 곧 인입 누락의 점수화(시스템 비종속 정합). 성적표에서 "인입 누락 기인" 태그로 분리 집계해 엔진 결함과 구분한다.
- 근거: 미포함 시 시험지가 코퍼스 범위에 종속됨 — 원칙 7 위반. 설계본부+외부 교차검토 공동 권고를 사용자가 승인.
- 헌법승격: 아니오(방법론 v1.2 §2 반영)

### DEC-015 — 청크 매핑은 별도 시트 (골든셋 본체 컬럼 금지)
- 출처: 시스템팀 export 가이드(coverage_map_goldenset_guide) 검토 (2026-07-08)
- 발생노드: 설계 / 이슈유형: `시스템 종속 위험`
- 상황: 시스템팀 가이드는 doc_key/point_id를 정답 앵커로 골든셋에 직접 기록하는 방식. point_id는 재청킹 시 바뀌는 값.
- 판정: doc_key/point_id 매핑은 채택하되 **별도 매핑 시트**로 — 시험지 본체는 불변, 재청킹 시 매핑 시트만 재생성. 검색 채점은 느슨(doc_key)/엄격(point_id) 2수준, 생성 채점(judge)은 별도 레이어로 병행.
- 근거: 본체 컬럼에 넣으면 재청킹마다 시험지 수정 = 원칙 7 위반의 뒷문. 시스템팀 조인 구조의 장점(자동 채점)은 매핑 시트로 동일하게 확보됨.
- 헌법승격: 아니오(방법론 v1.3 §2 반영)

### DEC-016 — 지시 외 변경: 사전 문의 원칙, 실행 시 보고 명시 필수
- 출처: RC 코퍼스판 검수 (2026-07-08, B5 OH 앵커 자진 확장 / B3 v3 비고 13셀 미명시)
- 발생노드: 수정 회차 / 이슈유형: `무단 변경`
- 상황: 수정 지시 범위 밖의 셀을 AI가 함께 변경. 한 건은 사전 공개 보고(수용), 한 건은 완료 보고 누락(전셀 diff로 검출).
- 판정: 지시 외 변경은 **사전 문의가 원칙**. 실행했다면 완료 보고에 변경 셀 전량을 건수로 명시. **미명시 변경이 검수(전셀 diff)에서 발견되면 내용과 무관하게 반려.**
- 근거: 등식 검수(DEC-012)는 행 단위만 잡는다 — 셀 단위 무단 변경은 diff로만 검출되므로 보고 의무로 막는다.
- 헌법승격: 아니오(검증규칙서 반영)

### DEC-017 — 검수받지 않은 산출물에 "합격/확정" 표기 금지
