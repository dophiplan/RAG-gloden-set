# OPEN_ISSUES.md — 미해결 보관소

> 실무 중 막힌 것·애매한 것을 **일단 여기 쌓는다**(안 잊히게).
> 사람이 풀면 `DECISIONS.md`로 옮기고, 같은 이슈유형이 2건 이상이면 `agent_triage`가 프로세스 결함으로 격상한다.
>
> **모든 항목은 반드시 `발생노드`와 `이슈유형`을 단다** (카테고리로 묶고 세기 위함 — 헌법 §6).

---

## 작성 규칙

각 항목은 아래 필드를 모두 채운다:

- **ID**: `ISS-{번호}` (예: ISS-001)
- **제품**: RC / RV / RM / HR
- **대상**: 어떤 문항·단위·파일인지 (예: RM-F09)
- **발생노드**: 어느 단계에서 나왔나 — `원본수집` / `커버리지맵` / `생성` / `1축` / `2축` / `3차` / `확정`
- **이슈유형**: 무슨 종류 — 아래 "이슈유형 사전"의 태그 중 하나(없으면 새로 만들고 사전에 추가)
- **내용**: 무엇이 막혔나 (1~2줄)
- **재개조건**: 무엇이 충족되면 다시 다룰 수 있나 (이게 없으면 영영 잊힌다)
- **상태**: `열림` / `해결대기(사람)` / `해결됨→DECISIONS`

> ⚠️ 발생노드·이슈유형이 비어 있으면 트리아지가 패턴을 감지할 수 없다. **빈칸 금지.**

---

## 이슈유형 사전 (태그 목록 — 새 유형은 여기 추가)

| 태그 | 뜻 | 보통 어느 노드 |
|---|---|---|
| `소스미발견` | 발췌가 어느 소스에서도 안 잡힘 (환각 의심 or 추출 문제) | 1축 / 2축 |
| `단위ID미지정` | 근거 페이지가 커버리지맵에 단위로 없어 citation_id를 못 붙임 | 커버리지맵 |
| `사양충돌` | 문서 간 값이 모순 (예: 권장 사양 A문서≠B문서) | 생성 / 확정 |
| `코드드리프트` | 같은 대상의 코드/ID가 단계마다 다름 | 생성 / 2축 |
| `권한근거없음` | 정답의 권한 주체가 근거 발췌에 실재하지 않음 | 생성 |
| `발췌불가` | 자료가 이미지본·표·덤프라 verbatim 발췌가 안 됨 | 원본수집 / 생성 |
| `표본설계미정` | TC 등 대량분의 표본 설계가 안 정해져 보류 | 커버리지맵 |
| `스키마구멍` | 스키마에 필요한 컬럼/필드가 없음 | 생성 |

## 현재 열린 이슈 (RM 1회 완주에서 발생)

### ISS-001
- 제품: RM
- 대상: RM-F09, RM-F21
- **발생노드**: 1축
- **이슈유형**: `소스미발견`
- 내용: 발췌가 errdef·자동매칭에서 안 잡혔으나, 이후 현행화 PDF에 실재 확인됨(F09 "올바르지 않은 라이선스 타입", F21 "중복 데이터/메일형식").
- 재개조건: 현행화 소스로 grounding하여 타당화할지 사람이 결정 → 결정되면 검증완료 처리.
- 상태: 해결대기(사람)

### ISS-002
- 제품: RM
- 대상: RM-MN08, RM-MN12
- **발생노드**: 커버리지맵
- **이슈유형**: `단위ID미지정`
- 내용: 발췌는 원문(관리자 p6/모바일 p7)에 실재하나, 해당 페이지가 커버리지맵에 단위로 미등록 → citation_id 연결 불가.
- 재개조건: 그 페이지가 커버리지맵에 이미 있으면 그 Unit ID 연결, 없으면 2줄만 새 단위로 추가 후 연결. (전체 재작성 금지)
- 상태: 해결대기(사람)

### ISS-003
- 제품: RM
- 대상: TLS 충돌 1건
- **발생노드**: 확정
- **이슈유형**: `사양충돌`
- 내용: TLS 관련 충돌 1건 미판정.
- 재개조건: 충돌 내용 확인 후 사람이 정본 값 판정.
- 상태: 열림

### ISS-004
- 제품: RM
- 대상: 헬프데스크 권장 사양 (macOS 10.15/최소10.13 vs 현행화 10.15~13.x · 네트워크 5.5Mbps vs 4.05Mbps)
- **발생노드**: 생성
- **이슈유형**: `사양충돌`
- 내용: 헬프데스크 문서의 권장 사양이 현행화/PDF와 다름. 헬프 단위만 박고 충돌 판정은 보류.
- 재개조건: 어느 문서가 정본인지 사람이 판정 → 충돌목록에서 확정.
- 상태: 열림

### ISS-005
- 제품: RM (전 제품 공통 가능성)
- 대상: TC 4,383 (대량 테스트케이스)
- **발생노드**: 커버리지맵
- **이슈유형**: `표본설계미정`
- 내용: 표본설계 미정으로 TC 전체 보류. 전수 데이터는 보관, 분모·미검토0 기준에서 제외.
- 재개조건: `TC_표본설계_{제품}.md`(층화표본 설계) 확정 시 → 표본만 문항화 활성화.
- 상태: 열림

### ISS-006
- 제품: 전 제품 공통
- 대상: 골든셋 스키마
- **발생노드**: 생성
- **이슈유형**: `스키마구멍`
- 내용: 검증규칙서 §3.3은 `answer_type`(single/multi_equivalent) 컬럼을 요구하나 14컬럼 스키마에 없음. 다중정답 많은 제품(RC·RV)에서 문제 소지.
- 재개조건: 다음 생성부터 `answer_type` 컬럼 추가하면 해소. (소급 안 함)
- 상태: 열림

> 같은 이슈유형이 2건 이상이면 여기에 자동으로 격상 기록된다.

- **`사양충돌` 2건** (ISS-003 TLS, ISS-004 헬프데스크) → **프로세스 결함 후보**:
