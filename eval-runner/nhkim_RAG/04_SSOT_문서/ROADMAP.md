# ROADMAP.md — 개발 로드맵

> 한 번에 다 만들지 않는다(헌법: 완벽 아니라 작동 → 굴리며 고친다).
> 작은 것부터 쌓고, 각 단계는 **독립적으로 쓸 수 있게** 만든다. 합격 기준을 통과해야 다음으로.

---

## 단계 개요

| 단계 | 만드는 것 | 왜 이 순서 | 에이전트 개입 |
|---|---|---|---|
| **1** | 검증 후처리기 (tools/) | 제일 손 아팠던 노동, 판단 없어 안전, 효과 큼 | 없음(순수 코드) |
| **2** | 오케스트레이터 + 핸드오프 + 상태/로그 | 1단계 도구를 흐름에 연결 | orchestrator·handoff·gate |
| **3** | 멀티제품 보드 + 영향분석 | 한 제품 흐름이 돌면 4개로 확장 | impact + UI |

---

## 1단계 — 검증 후처리기 (가장 먼저)

상세 스펙: `specs/STAGE1_검증후처리기.md`

**범위**: verifier 1축 결과(JSON)를 받아 status별 자동 처리 + 2축 배치 자동 분할 + 결과 집계.
판단(통과/탈락)은 안 함 — 분류·정리·추림만.

**합격 기준**:
- [ ] verify_1axis.json 입력 → e_trap 자동완료 / ok_uncited 출처채움 / partial·missing 사람볼것 분리
- [ ] missing을 자동완료로 올리지 **않음** (헌법 §3.2)
- [ ] 골든셋 → 15문항 배치 jsonl 자동 분할 (첫 줄 안내문 포함)
- [ ] 외부 판정 결과 JSON 모아 타당/의심/반려 집계 + 누락 id 탐지
- [ ] 모든 처리에 로그 남김 (logs/)
- [ ] RM 실제 데이터(130/144건)로 회귀 테스트 통과

---

## 2단계 — 오케스트레이터 + 핸드오프

**범위**: 노드 자동 전환, state.json 관리, 핸드오프 내보내기/받기, 사람 게이트 멈춤, 로그.

**합격 기준**:
- [ ] 한 제품을 커버리지맵→…→확정까지 state.json으로 추적
- [ ] 핸드오프 노드에서 "생성과 다른 AI에 돌려라" 안내 + 결과 받으면 다음으로 (헌법 §2.1)
- [ ] 사람 게이트(설계·확정)에서 멈추고 human_queue에 등록
- [ ] 막힌 것 OPEN_ISSUES 등록(태그 필수) + triage 호출
- [ ] 로그로 역추적 가능, 노드별 부분 재실행 가능

---

## 3단계 — 멀티제품 보드 + 영향분석

**범위**: 4제품 전체 보드(2층 UX), 영향분석 에이전트.

**합격 기준**:
- [ ] 전체 보드에 4제품 현재 노드·진척·상태 + ✋사람대기 집계
- [ ] 제품 클릭 시 7노드 파이프라인 펼침
- [ ] 4제품 병렬 진행(각자 state)
- [ ] 원본 추가 시 영향분석이 "어디부터 다시" 계획 제시(citation_id 추적), 전체 재작업 안 함
- [ ] 지표(커버리지율·진척·반려율·사람대기) 표시

---

## 전 단계 공통 약속

- 각 단계 산출물은 헌법을 위반하지 않는다(특히 §2.1 자기검증 금지, §2.4 게이트).
- 모든 자동 동작은 로그를 남긴다(역추적·영향분석 토대).
- 노드/도구는 독립적으로 — 한 곳을 고쳐도 다른 곳이 안 깨지게(굴리며 고치기 위함).
- 실제 RAG(eval-runner)는 본 시스템 **밖**. 골든셋 완성본이 그 입력이 될 뿐, 여기서 만들지 않음.
