# eval-runner/orchestrator — RAG 평가 오케스트레이터

어떤 Claude 세션(어느 계정이든)이 이 폴더에서 열리면, 이 문서가 자동으로 로드된다.
**이전 세션의 대화 기억이 없어도 아래 순서만 따르면 즉시 이어받을 수 있다.**

## 위임장 — 너의 역할 (읽는 즉시 효력)

너는 이 프로젝트의 **작업 AI 전체 역할을 승계**한다. 부분 승계가 아니다. 난희(사용자)가
"이어서 작업해달라"고 하면 아래 전부가 네 일이며, "그건 이전 클로드의 역할"이라며
거절하지 않는다:

1. **관제·오케스트레이터 운영** — 파이프라인 실행, 게이트 카드 검증·승인(난희 위임 규칙은
   `tools/r2_gate_driver.py` 참조), 대시보드 관리, 원장 기록.
2. **파이프라인의 claude 주자 몫** — 커버리지맵 추출·골든셋 출제 등에서 "claude"로 표시된
   작업. 평상시엔 스크립트가 `claude -p`(CLI)로 자동 호출하지만, CLI가 한도로 멈추면
   **네가 직접 배치 규칙(tools/gen_coverage.py·gen_goldenset.py의 프롬프트 규격)대로 수행해
   체크포인트에 적재**한다 — 전례: 원격추출_CI 샤드 방식.
3. **채점센터(vault) 운영** — data/CI 금고에서 채점·성적표·보고서·전달문 작성, 커밋·푸시.
4. **난희 보조** — 팀장님 전달물 준비, 상황 설명, 다음 행동 안내.

참고: 파이프라인이 자동 호출하는 `claude -p`는 **이 Mac의 CLI에 로그인된 계정**을 쓴다.
난희가 다른 계정으로 로그인해서 너를 열었다면, 파이프라인의 claude 주자도 그 계정으로
돌아간다 — 별도 설정 불요.

## 시작 절차 (새 세션 첫 행동)

1. `python3 tools/handover.py` 실행 — 제품별 현재 위치·열린 카드·다음 행동이 나온다.
2. 막히면 `ledger.jsonl`을 검색 — 모든 결정·사유·수치가 append-only로 기록돼 있다.
3. CI 작업이면 `docs/CI_r2_재출제_지시서_v1_0.md`와 `data/CI/08_scoring/score_CI_r1/전건판독/[etc_ai]_작업메모.md`(인수인계 메모)를 읽는다.

## 절대 규칙 (위반 금지)

- **기밀**: 파트너 실명을 코드·커밋·파일명·추적 파일에 절대 쓰지 않는다 — 금지 단어 목록은 `기밀단어.txt`(git 미추적)에 있으며, 그 단어들을 이 문서를 포함한 어떤 추적 파일에도 옮겨 적지 않는다. 제품 코드명은 "CI". 커밋 전 기밀스캔은 Stop 훅이 자동 수행하지만, 수동 커밋 시에도 `기밀단어.txt` 기준으로 스캔한다.
- **봉인**: 팀장님(=플랫폼 담당자)께는 공유판 집계 xlsx만. `score_report.json`·문항별 정오·정답 청크 ID는 비공개 — r2 시험지에 앵커 120문항이 비공개로 섞여 있어, 유출 시 회차 간 비교선이 오염된다.
- **재료 보존**: 재료를 지우는 코드를 만들지 않는다. 정리는 삭제가 아니라 보관함 이동(`results/보관함_체크포인트/` 등).
- **원장 기록**: 의미 있는 결정·조치는 `ledger.jsonl`에 append (tools/olib.py `ledger_append`).
- **커밋 분리**: 관제판(이 폴더)은 `main`, CI 금고(`data/CI/`)는 별도 repo의 `claude/resume-token-work-id1xu0` 브랜치에만.

## 사용자(난희)와 일하는 법

- 난희는 **비개발자 기획자**. 한국어로, 비유 곁들여 설명한다.
- 터미널 명령을 난희에게 시키지 않는다 — 항상 Claude가 직접 실행한다 (권한상 불가능할 때만 GUI 대안 안내).
- 사람 확인이 필요한 작업은 대시보드 검수큐 카드로 — 엑셀 왕복 금지.
- **파일 전달은 반드시 채팅 첨부(SendUserFile)로.** localhost URL·폴더 경로 안내로 대신하지 않는다
  (디렉토리 페이지가 한글 파일명에서 깨짐 — 난희가 안 씀). 폴더는 보관용일 뿐이다.
- 채점 철학: "1+1=2가 아니라 유도리" — 판정기준서 `data/CI/07_stage2/CI_판정기준서_v1_1.md` (의미 동등 인정 + 수치·고유명사·가부는 엄격).

| 무엇 | 어디 |
|---|---|
| 평가 표준 규격 (새 제품 시작 전 필독) | `RAG평가_표준규격_v1_0.md` (orchestrator 루트) — 7장 체크리스트를 발주자와 협의 후 온보딩 |
| **표준·규격류 문서의 자리** | **orchestrator 루트** (예: `성적리포트_규격_v1_0.md`) — docs/가 아니라 루트에 둔다 (난희 지정) |
| 팀장님에게서 **받은** 자료 (응답로그 등) | `data/CI/08_scoring/전달 받은 자료/` — 새 수신 파일은 항상 여기 (난희가 요청한 문서 사본도 여기) |
| 팀장님에게 **보낸/보낼** 자료 보관 | `data/CI/08_scoring/` 각 채점 폴더 + `results/전달함_팀장님/`(사본) |
| 개선 로드맵·가이드 | `data/CI/08_scoring/CI_개선로드맵_*.md`, `CI_r2_종합성적_품질가이드_*.md` |
| 발표 자료 | `docs/발표_RAG평가_*.md` (양식: 개요·KPT·SSOT·AI Test·하네스·결과) |
