① 개요

경과RAG 시스템에서 크롤링하여, 그 기준으로 평가를 시작했습니다.
발견AI 입장에서는 "어떤 것이 명확한 정답인가"를 알 수 있는 데이터 정본이 중요했습니다. 크롤링 데이터는 마케팅 문구가 섞여 미묘한 답변도 정답이라 헷갈리는 상황.
실측: 구버전 문서 118건 혼입 · 문서 간 수치 충돌 11건 · "제공 예정" 마케팅 문구를 근거로 없는 기능을 답할 위험 확인
결과업계가 주장하는 98% 수준 대비, 우리 실측은 TOP5 정답률 50% 미만 (r5 엄격 43.8% · 관대 50.7%)에 머문 이유 중 하나.
투자임베딩·검색 성능을 끌어올리려면 GPU 등 인프라 투자가 병행돼야 하며, 팀장님 측의 투자·검토가 필요한 부분입니다.
결론 — 정본을 정해놓고 시작해야 정확한 답변과 검증이 가능합니다.

전체 그림 — 한 장으로

"시험지는 우리가 만들고, 응시는 시스템이 하고, 채점은 우리가 한다."

② 회고 — KPT

Keep · Problem · Try

Keep — 잘된 점, 유지할 것

  • AI 활용 방식 멀티모델 교차검증 — 생성(Claude) → 검증(Kimi·GPT) → 확정(사람), 자기검증 금지. 7월엔 2개 AI 병행 생성으로 확장 → 구버전 118단위를 통합 전 적발
  • 업무 진행 방식 30문항 배치 + 계리 등식 검수("숫자 없는 완료는 반려") + 판례·결정(DEC 원장) 누적 — 틀린 만큼 규칙이 강해지는 구조
  • 협업 방식 팀장님과 라운드 루프 정착 — 개선안을 예측치와 함께 회신하고 실제 적중(r5 예측 68/60). 정답키 공개 같은 정책은 사람이 결정
  • 생산성 향상 1축 검증 스크립트화(문자대조) · eval-runner 자동 채점 · match_corpus 자동 대조 — RM 인입 겹침 0건을 파일럿 전에 발견
  • 재사용 가능한 방법 방법론 문서 5종 — 제품 설정 블록만 바꾸면 어느 제품에나 적용. RC·RV·RM·HR 4제품에 같은 체계 적용 완료

Problem — 문제, 부족했던 점

  • AI 활용 한계 LLM은 "발췌가 원문에 글자 그대로 있는지"를 못 믿는다(→ 1축을 스크립트로 분리) · "핵심만 알아서" 맡기면 임의 누락(36문항 사례) · LLM judge가 형식에 반응하고 실질(소스 근거)을 놓침(RM 2축 실증)
  • 기술적 문제 측정 시스템이 진화하면 채점기가 늙는다 — 신형 거절 표현 오탐 → 채점기 개정 + 전 회차 소급 재채점 규칙으로 대응 · r2 표면 하락의 실체는 URL 누락으로 인한 측정 불능
  • 일정 지연 원인 코퍼스 전체가 커서 한 번에 못 끝냄 → 배치·마일스톤 관리로 전환 · 세션 간 산출물을 사람이 수동 복사하는 셔틀이 병목 → 자동화 착수 배경

공통점: 문제가 발견되면 은폐가 아니라 판례로 기록·정정 — 검수 자신의 오반려 2회도 공개 정정 후 "합집합 원칙"으로 규칙화

Try — 다음 시도

  • AI 개발 스킬 적용 오케스트레이터로 수동 셔틀 기계화 — 단, 도구도 산출물: 검수 통과 후 가동
  • 개발 프로세스 개선 골든셋 v2.0 봉인 체제(시험지 고정 강화) · 채점기 소급 재채점 상시화 · 판례 2단계(초안→발효)
  • 협업 방식 개선 예측→검증 루프 정례화 · 인입 누락 리포트 상시 산출 · 지식 소스 위계 합의 추진

파이프라인의 자정 능력 — 검수가 잡아낸 것들

생성 ≠ 검증 ≠ 확정, 3권 분립이 실제로 작동한 증거

  • 구버전 118단위 적발 AI-2가 커버리지맵 B2에 구버전 문서를 잘못 포함 → 2개 AI 병행 대조로 통합 전 적발
  • 반려는 일상적 품질 루프 커버리지맵 B3 반려(사양 정본 대조 미수행 등 4건) · B5 결함 4건 확인 → 수정본 재검
  • 감사에서 오계산 적발 RV B6 외부 감사에서 누적 실격 오계산 적발·정정, 게이트 스크립트 정규식 결함 발견
  • LLM 판정의 한계 실증 RM 3차 교차검토 — LLM 2축 판정이 소스 근거와 무관하게 갈린 것을 원문 대조로 적발. "일괄 규칙은 소스 실측 뒤에만"
  • 검수 자신의 오판도 공개 정정 오반려 2회를 기록·정정하고 "합집합 원칙"으로 판례화 — 틀린 만큼 시스템이 강해지는 구조

누적 판례·결정은 DEC 원장으로 규칙서에 계속 편입된다

사람이 세션 사이에서 파일을 복사해 나르던 것을 "우체통 + 계정 기반 CLI 앙상블"로 대체합니다.
