## P0 — 즉시 (실데이터 영향)

### P0-1. 골든셋 문항 ID 충돌 → 문항 76개 조용한 증발 [Critical · 실측 확정]
- `gen_goldenset.py:318` 차수 시작 번호가 "인용 성공 단위 수" 기준이라, 미인용 발생 시 다음 차수가 직전 차수와 같은 번호를 재사용. **서로 다른 문항이 같은 ID**를 받음 (실측: RC2-555 = 10차 "브랜드 경쟁력" 문항 ≠ 11차 "고객 평가" 문항).
- 마감(CLOSING)이 뒤 문항을 조용히 버리고 `"ID 중복": 0`을 하드코딩(:426) — **본검수 실측: RC2 배치 965행 vs 통합 대장 889행, 중복 ID 76종·76행 드롭. RV 93건·RV2 3건(1차 검수 실측).**
- 영향: 커버 회계는 "커버됨"인데 문항은 대장에 없음. 반려 코드 지목·판정·채점의 ID 참조가 모호해질 수 있음.
- 수리: ① 시작 번호 = 기존 발행 최대 번호+1 ② CLOSING 중복 발견 시 드롭 금지 → HALT+카드 ③ 하드코딩 0 제거 ④ **증발 76문항 재검** (해당 단위 재출제 여부 사람 결정 — v2 존치/v3 반영은 난희 결정 필요)

### P0-2. ⑥ 캘리브레이션 판정지 어휘 불일치 — 다음 면접이 구조적으로 막힘 [High]
- 사람 드롭다운 = "합격,불합격" 2단(`judge_run.py:127`), 채점관 = "합격|부분|0점" 3단, 비교는 문자열 정확일치(`calibration.py:80`). 사람이 전부 동의해도 "부분/0점"건은 전부 불일치로 계산 → 90% 임계 미달 고착.
- 동반 결함: 30건 중 일부만 기입해도 기입분만으로 일치율 계산 → 10건 기입·9건 일치 = 90% 통과.
- 수리: 드롭다운 3단으로 통일 + 전건(30건) 기입 검증 추가.

### P0-3. E형 채점의 "명시적으로 언급" 패턴 — 환각을 거절 성공으로 오채점 [High]
- `run_score_v11.py:36` 거절 패턴에 "명시적으로 언급" 포함 → "…라고 명시적으로 언급되어 있습니다"(존재 단정=환각)도 거절 매치 → E형 pass. 이 방향 오분류는 사람 검토망(E형환각 건만 열람)에도 안 걸림.
- 동반: 결측/빈 answer가 E형이면 자동 pass(`:398-403`).
- 수리: 패턴 제거(또는 부정형 앵커), 빈 answer는 pass 금지. 채점기 변경 = 규칙 D 소급 재채점 자동 발동(정상 경로).

### P0-4. 데모 모드(?demo=)가 실데이터에 기록 [High]
- 캡처용 가짜 팝업의 판정 버튼이 실제 `calin-set`/`s2diff-set` POST를 실행(`index.html:325-336` + 팝업 핸들러) — 데모 ID(RC2-414)가 실물 형식이라 실제 판정지 셀을 덮을 수 있음.
- 수리: 데모 상태에서 기록 API 차단(no-op + 토스트).

### P0-5. state.json 무잠금 + 장시간 러너의 낡은 스냅샷 되쓰기 [Critical급 구조]
- `save_state` 락 없는 전체 덮어쓰기. 출제 러너가 state를 20~40분 들고 있다가 되씀(`gen_goldenset.py:273→361`) → 그 사이 사람이 한 반려/승인/온보딩이 **통째로 증발** (반려했는데 회계가 반려 전으로 복원되는 시나리오).
- 수리: 파일락(fcntl) + 저장 직전 재로드 후 자기 제품 키만 갱신. 이중 승인(대시보드×폰 동시) 잠금도 같은 수리로 해결.
