# Vertex AI Search 비교 실측 보고 — 같은 시험지·같은 코퍼스 (2026-09-03)

> 발주: 본부장님 미션(9/2) "Vertex와 비교, 속도 1~2초, 성능 병행" · 작성: 채점센터(난희·claude)
> 방법: CI 시험지 488문항(비E형 447 + 자료 부재 E형 41)을 **자사 RAG(팀장님 플랫폼, r4/9/1)** 와 **Google Vertex AI Search**에 같은 코퍼스(21,354청크)로 응시시켜 **같은 채점기**로 채점.
> 표기: "자사" = 팀장님 플랫폼 r4(2단 판단 적용) · 검색축은 r4 동형인 A(qr_off, 9/2) 기준.
> 원칙: 실측 없는 숫자 없음 · 목표 수치 없음 · 비교 조건 차이를 먼저 밝힘(2절).

## 5. 속도 상세 (Vertex, 447문항, 클라이언트 왕복)

| | P50 | P95 | 평균 |
|---|---|---|---|
| 검색만 | 0.24초 | 0.37초 | 0.25초 |
| 검색 + 답변 생성 | 4.0초 | 6.2초 | 4.1초 (최대 11.6초) |

- 답변 생성(LLM)이 전체 지연의 **약 94%**. 검색 자체는 0.24초.
- 자사 31초(P50)는 리랭크 폭 50(CPU) + ReAct 다회 검색 포함 서버 내부 시간. GPU 도입 시 리랭크 ~1초(플랫폼 확인) — 그래도 ReAct 턴 수가 남는다.
- **같은 단위로 재려면**: 자사도 클라이언트 왕복으로 1벌, 또는 Vertex를 자사 서버에서 호출해 1벌. 표준 후보 #1(속도·비용 축 — 로그에 latency 필드)이 필요한 이유.

## 6. 판단에 참고하실 것 (결정은 본부장님·플랫폼)

1. **품질**: 자사가 검색(+16%p)·환각(0 vs 3)에서 앞선다. 단 이는 리랭크 폭 50(GPU 전제)·ReAct·2단 판단 프롬프트의 결과이며, 운영 형상(폭 10·CPU)과 Vertex의 격차는 훨씬 작다.
2. **속도**: Vertex 기준 "답변 완료 4초·검색 0.24초". 자사가 1~2초에 가려면 **ReAct 턴 제한 + GPU 리랭크 + 스트리밍(첫 글자)** 이 필요하고, 그 형상의 품질은 **다시 재야** 한다(속도-품질 곡선의 새 점).
3. **정의 확정 요청**: "1~2초"가 ① 검색 결과 표시 ② 첫 글자 ③ 답변 완료 중 무엇인지. ①이면 자사 검색 단계 실측이 필요하고, ③이면 Vertex도 미달이다.
4. **다음 실험(제안)**: (a) 자사 "속도 형상"(ReAct 1턴·폭 50 GPU·짧은 답) 1벌 → 같은 채점 → 곡선의 새 점. (b) Vertex에 **원본 문서**를 넣어 자체 청킹 판 1벌 → Vertex 본래 실력. 둘 다 시험지·채점기는 그대로.
