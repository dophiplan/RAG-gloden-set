## 3. 요청 ④ — 실제 리랭크 창으로 다시 잰 결과 (이번 회신의 핵심)

9/9 회신의 "앞 256자 안/밖"이 대리 지표라는 교정을 받아, 이번 로그의 `rerank_input_start/end`(리랭커가 실제로 본 구간)로 정답 발췌 위치를 다시 판정했습니다.

| 집합 | n(판정 가능) | 정답 발췌가 **실제 창 안** | 창 밖 |
|---|---|---|---|
| **적중 문항**(top5에 든 정답 청크) | 271 | **233 (86%)** | 38 |
|   └ 표 청크 | 118 | 96 (81%) | 22 |
|   └ 문장 청크 | 153 | 137 (90%) | 16 |
| **후보 안**(6~50위 — 리랭커가 저평가) | 32 | **11 (34%)** | **21 (66%)** |
|   └ 표 청크 | 22 | **6 (27%)** | **16 (73%)** |
|   └ 문장 청크 | 10 | 5 (50%) | 5 |

- 창 길이 중앙값 256, 창 시작 위치 중앙값 206자(첫 자에서 시작하는 창은 4%) — window 모드가 정상 작동함을 확인했습니다(교정 감사합니다).
- 그런데도 **적중이면 86%가 창 안, 저평가면 66%가 창 밖**입니다. 표 청크에서는 27% vs 81%로 격차가 더 큽니다. 즉 대리 지표가 아니라 기전 자체가 맞았습니다: **리랭커가 정답 문장을 보면 올리고, 못 보면 내립니다.** 표 청크에서는 질의 용어 밀집 창이 헤더 행이나 다른 행에 잡혀 정답 행을 비켜갑니다(정답 위치 중앙값 410자, 창 시작 중앙값 414자 — 바로 옆인데 어긋남).
- **512 확대의 실측 근거**: 후보 안 21건(표 16)이 "창을 넓히면 정답이 들어오는" 자리입니다. 단, 이 21건은 v3.1 미적중 154의 14%이고, 나머지 119건(77%)은 후보 50에도 없어 창 문제가 아닙니다. 512는 **병행 카드**, 1순위는 여전히 1차 회수(표 청크의 임베딩·BM25 표현)입니다.

## 4. 표 회수 실패 119건 — 1차 회수 문제의 크기가 변하지 않았습니다

- v3.1 미적중 154 중 후보 밖 119(표 80). 9/7(v2)에는 157 중 119(표 84). **재청킹 두 번(v3·v3.1)이 1차 회수 실패 수를 거의 못 줄였습니다.**
- 청크 모양(상한·헤더 반복·record_key)은 좋아졌는데 하이브리드 회수는 같다는 것은, 문제가 **청크 경계가 아니라 표 청크의 검색 표현**(임베딩이 표 행을 질의와 못 잇고, BM25 어휘도 표 안 값에 약함)에 있다는 뜻입니다. 남은 지렛대(채택은 귀측):
  1. 표 행을 **자연어 문장으로 병기**(예: "열 제목: 값" 문장을 청크에 덧붙임 — 임베딩·BM25 양쪽에 걸림)
  2. **record_key(절 제목·FAQ 타이틀)를 임베딩 텍스트에 포함**(99.4% 채워졌으니 바로 가능)
  3. 표 청크 전용 **dense 가중 조정** 또는 후보 폭 확대(50→100)로 1차 회수 문턱 낮추기 — GPU 전환으로 비용이 사라짐(§5)
  4. 리랭크 입력 512(후보 안 21건)

## 5. 속도 — GPU 전환 실측 (본부장님 미션과 직결)

| 검색 단계(LLM 0) | v3 (CPU, 9/8) | **v3.1 (GPU fp16, 9/9)** |
|---|---|---|
| search_ms P50 / P95 | 28,744 / 54,343 ms | **492 / 614 ms** |
| 내부 분해 P50 | — | rerank **112** · vector 241 · embed 23 ms |
| 동시성 | — | 2 워커(단일 요청 지연과 다름) |

**58배**입니다. 9/9 회신의 "31초의 본체는 검색·리랭크(CPU)"가 그대로 확인됐고, 이제 검색 단계는 0.5초라 **답변 완료 4~5초(Vertex 수준)의 과제가 LLM 생성 단계로 넘어갔습니다.** 다음 생성축 회차(r6)에 `search_ms`처럼 생성 단계 지연 필드가 있으면 속도 곡선을 완성할 수 있습니다. 또 하나 — GPU에서 리랭크 112ms라면 **후보 폭 50→100, 입력 256→512는 이제 비용이 아니라 설정 문제**입니다.

- **앵커 88→83**: v3 채택 시 기준선을 88로 재설정했을 텐데 v3.1이 83이라, 어느 판을 기준선으로 할지 귀측 채택 선언이 필요합니다. 채점센터는 v3·v3.1 두 리포트를 모두 보관합니다.
