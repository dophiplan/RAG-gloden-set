## 2. 회고 (KPT)

### 1) Keep — 잘된 점 / 유지할 것

**AI 활용 방식 / 모델 정보**
- 3권 분립 유지·강화: 출제(Claude) · 채점(Kimi k2.6) · 교차(Codex) + 결정은 사람. 자기 시험지 자기 채점 금지
- **이중판정 정착**: 답변 채점 488문항을 Kimi 정판정 × Claude 교차 검토 — 일치율 90.8%, 갈린 45건만 원문 대조로 확정. "AI 판정을 AI가 견제"하는 구조가 실전에서 작동
- **함정 면접**: 사람이 도메인(일본어)을 몰라도 채점관을 검증 — 정답을 아는 변조 답안 24개를 심어 23개 적발 확인 후에만 본채점 허용

**개발/업무 진행 방식**
- **앵커 문항 발명(이번 달 핵심)**: 시험지를 갈아엎으면서도 전 회차 문항 120개를 비공개로 재사용 — 회차 간 비교선 유지. "시험지를 개정하면 향상을 못 잰다"는 딜레마를 구조로 해결
- 향상 주장 규율: 잣대(시험지·채점기·임계값) 동결 비교에서만 "올랐다"고 말함. 신규 지표 첫 측정은 기준선이지 향상이 아님 — 이 원칙으로 모든 수치가 반박 가능성에서 생존
- 사고도 판례로: 기밀 단어 유출(자동 스캔 훅이 적발 → 이력 정리), 오채점 사고(→ 제품별 채점기 가드 + 비상 정지 버튼) — 사고 2건이 재발 방지 장치 2개가 됨

**협업 방식**
- **"역지사지 회신" 정착**: 플랫폼팀에 성적만 던지지 않고 ① 수고 인정 → ② 실측 근거 → ③ 실험 방법 → ④ 탈출구("효과 없으면 버려도 됨") 구조로 회신 → 제안 3건을 플랫폼팀이 전부 하루 안에 실험으로 회신하는 루프 형성
- 이견은 실측으로 해소: "옵션 A/B 차이 없음 → 폐기" 판단을 문항 짝지음 비교(+7/-3, 통계적 동점)로 검증해 지지 · "대표 지표를 생성축으로" 제안을 데이터(1턴 검색 실패 213건 중 136건을 다회 검색 루프가 구제)로 실증해 수용

**생산성 향상 사례**
- 로그 도착 → 당일 채점 → 당일 다음 실험 지시: 6~7월의 회차당 수일 → **8월엔 하루 3회차**
- 진단 자동화: top_k=50 로그 1벌로 미적중 213건을 "순위 문제 35% / 회수 문제 57% / 정밀도 8%"로 기계 분해 → 다음 개선의 조준점이 사람 판독 없이 나옴

**재사용 가능한 방법**
- **RAG 평가 표준 규격 v1 제정**: 측정 철학 5조 · 지표 체계 · 시험지 구성(앵커 20~30% 등) · 절차 관문(캘리브레이션·함정면접·이중판정·top_k 진단) · 오픈 게이트 골격 — 표준 본문은 불변, 제품별로는 **커스텀 협의 체크리스트 10항**(용도·통과선·플랫폼 구조·로그 형식·기밀 수준 등)만 발주자와 협의

### 2) Problem — 문제 / 부족했던 점

**기술적 문제**
- 판정기준서 파일이 폴더 이동으로 유실된 채 기본 기준서로 판정이 진행됨(실측 불일치율은 낮아 결과 수용, 파일 복원 + 원장 기록으로 수습) — "규칙 파일의 소재도 검증 대상"이라는 교훈
- 관제판 범용 채점기가 신규 제품 로그를 잘못 채점(전건 0점 가짜 회차 생성) — 제품별 채점기 라우팅 가드 + 비상 정지 버튼으로 수습·재발 차단

**AI 활용 한계**
- LLM 채점관 간 판정 불일치 9.2%(45/488) — 문항 판정(1.7%)보다 답변 채점에서 크게 증가. 유도리(의미 동등) 판단은 채점관마다 갈림 → 이중판정 + 원문 대조 확정 절차가 필수임을 실증
- 다회 검색(ReAct)으로도 못 푸는 영역 실측: 자료 자체가 없으면 15턴을 돌아도 없고, 그때 지어냄(환각 6/41) — 검색 반복으로는 환각을 못 막는다

**협업 문제**
- 측정 대상 시스템의 내부 구조(다회 검색 루프 등)를 뒤늦게 인지 — 검색축만 재면 제품 반쪽 측정이 될 뻔함. 표준 체크리스트에 "플랫폼 구조 확인" 항목으로 편입
- 세션(작업 AI) 단절 5일간 업무 정지 경험 → **인수인계 체계 구축**: 저장소가 기억을 보유(CLAUDE.md 위임장 + 실시간 현황 브리핑 생성기 + append-only 원장)하여 어느 세션·계정이든 즉시 승계

**일정 지연 원인**
- 구독 한도로 AI 주자가 주기적으로 정지 → 이어달리기(체크포인트 승계)·원격 세션 대타·시간제 라운드로 흡수. 근본 해결은 아니며 용량 계획 필요

### 3) Try — 다음 시도

**새로운 기술 적용**
- 리랭크 대상 확대(10→30~50) 검증: 미적중의 35%가 "후보에 있는데 정밀 정렬 구간 밖" — 설정 하나로 top5 +8~17%p 예상, 로그 도착 즉시 검증

## 3. SSOT 관리현황

**SSOT 문서/자료 관리 방식**
- **원장(ledger.jsonl, append-only)이 유일 정본**: 모든 결정·수치·사유·사고를 5,500여 건 기록. "세션 기억"이 아니라 원장이 기억 — 어느 AI 세션이 와도 원장 재생으로 동일 상태 복원
- 이원 저장소: 관제판(파이프라인·도구, main) / 채점센터 금고(문항·정답·채점, 비공개 별도 저장소) — 정답키 무결성과 기밀을 저장소 경계로 보호
- 규칙의 정본: 판정기준서 v1.1 · 표준 규격 v1 · 제품별 협의서 — 문서 위치를 CLAUDE.md 위치 지도에 등록해 세션이 자동 인지

**업데이트 주기 및 갱신 프로세스**
- 갱신은 사건 단위 즉시(작업 종료 훅이 자동 커밋·푸시 + 기밀 스캔 관문) — "나중에 정리"가 구조적으로 불가능
- 표준 규격은 "두 제품 이상에서 유효할 때만" 개정 — 버전 업 + 원장 기록 + 소급 여부 명시

**최신성 유지 (Drift 방지)**
- 관제 대시보드의 상태·성적 표시를 하드코딩에서 **산출물 파일 실측 자동 계산**으로 전환 — 문서·화면이 실제와 어긋나는 drift를 원천 차단 (8월에 실제 drift 2건 발견·수리)
- 인수인계 브리핑은 문서 저장이 아니라 **실행 시점 생성**(상태 파일+원장+프로세스 실측) — 낡을 수 없는 구조

## 5. 하네스 구조

**아키텍처 개요**

**적용 범위 및 구성 요소**

**기존 방식 대비 개선점**
- 사람의 세션 간 수동 셔틀 → 무인 파이프라인 + 사람은 게이트 결정만 (7월 발표의 "자동화 계획"이 8월에 실전 가동됨)

**운영 중 발견된 이슈 및 보완**
- 오채점 사고(범용 채점기가 신규 제품 로그 처리) → 제품별 라우팅 가드 + ⏹ 비상 정지 버튼
- 반려 잠금이 정상 재시도까지 차단하는 모순 → 재시도류 카드 잠금 예외
- 죽은 체크포인트가 진행 패널에 잔상 표시 → 단계 통과 시 자동 숨김
- 원칙: 이슈는 은폐가 아니라 원장 기록 + 재발 방지 장치로 전환 (8월 수리 이력 전건 원장에 실재)
