# [작업 지시] 3차 교차검토 투입용 압축본 제작 (STAGE2 → 3차 준비)

너는 이 작업을 처음 받는 작업 AI다. 아래 스펙대로 **파이썬 스크립트(make_3rd_input.py)를 작성**해라. 실행은 사용자가 로컬에서 한다. 너는 판정하지 않는다 — 기계적 필터·요약·패키징만 한다.

## 배경 (한 줄)
RC 골든셋 893문항의 2축 판정(타당 861/반려 28/의심 4)이 끝났다. 다음 단계인 3차 교차검토(다른 모델이 수행)에 넣을 입력을 만든다. 893건 전체 JSON은 너무 크므로, 검토에 필요한 정보만 남긴 압축본이 필요하다.

## 입력 (사용자 로컬 경로)
- `inputs/2axis_input_B01.json` ~ `B30.json` — 문항 본문 (id, type, question, gold_answer_required, answer_type, pass_criteria, evidence_excerpt, citation, acl_level)
- `results/2axis_result_B01.json` ~ `B30.json` — 2축 판정 (id, verdict, answer_type_seen, checks, reason, fix_hint)

## 출력: `3rd_input.json` 하나
```json
{
  "meta": {
    "total": 893,
    "verdict_counts": {"타당": N, "반려": N, "의심": N},
    "made_from": "2axis results B01~B30"
  },
  "flagged": [
    // 반려·의심 전건 (32건 예상): 문항 본문 + 판정 전체를 병합
    {
      "id": "...", "type": "...", "verdict": "반려",
      "checks": {...}, "reason": "...", "fix_hint": "...",
      "question": "...", "gold_answer_required": "...",
      "answer_type": "...", "pass_criteria": "...",
      "evidence_excerpt": "...", "citation": "..."
    }
  ],
  "passed_summary": [
    // 타당 전건 (861건 예상): 경량 요약만
    {"id": "...", "type": "...", "reason": "..."}
  ]
}
```

## 규칙
1. **병합 키 = id.** inputs와 results를 id로 조인한다. 조인 실패(어느 한쪽에만 있는 id)는 0건이어야 하며, 있으면 스크립트가 에러로 멈추고 목록을 출력한다.
2. **flagged에는 원문 그대로** — 문항 필드와 판정 필드를 축약·수정 없이 담는다(3차가 원문 대조를 해야 하므로).
3. **passed_summary는 3필드만** — id·type·reason. (3차의 역검출용: reason이 빈약한 '타당'을 찾는 데 쓰인다.)
4. 인코딩 utf-8, ensure_ascii=False, indent=2.
5. E형의 evidence_excerpt=null은 null 그대로 유지.

## 스크립트 자가검증 (실행 끝에 출력, 등식 안 맞으면 경고)
- 총 병합 건수 = 893
- flagged 수 + passed_summary 수 = 893
- verdict_counts 합 = 893
- 조인 실패 0
- flagged 각 건의 필수 필드 결측 0

## 사용자 실행법 (스크립트 상단 주석에 포함시켜라)
```bash
cd ~/eval-runner/tools
python3 make_3rd_input.py    # inputs/, results/ 를 읽어 3rd_input.json 생성
```

## 완료 보고
스크립트 파일 + 실행 결과의 자가검증 수치(위 5개 등식)를 함께 제출.
