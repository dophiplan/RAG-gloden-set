# [작업 지시] RC 골든셋 STAGE2 — 2축 검증 준비 및 실행 절차

두 부분으로 구성된다. **PART A는 AI-3(패키징 작업)에게**, **PART B는 송하(Kimi 투입 실행)에게** 해당한다.

---

## PART A — AI-3: 2축 입력 패키지 생성 지시

### 목적
STAGE1 확정 골든셋 893문항(G-B1~G-B6, 6파일)을 Kimi 2축 판정에 넣을 JSON 배치로 변환한다. 너는 생성자이므로 **판정에 관여하지 않는다** — 기계적 변환·패키징만 한다.

### 입력
G-B1_SPEC(218) · G-B2-1(265) · G-B2-2(113) · G-B2-3(40) · G-B3_TERMS(57) · G-B4_NOTICE(61) · G-B5_BROCHURE(42) · G-B6_WEB(97) — 합 893.

### 변환 규격 (judge_prompt_2axis_표준 v1의 입력 스키마 그대로)
문항 1건 → JSON 1객체:
```json
{
  "id": "RC-A001@G-B1",
  "type": "A",
  "question": "...",
  "gold_answer_required": "...(정답 필수 포함 요소 전문)",
  "answer_type": "single | multi_equivalent",
  "pass_criteria": "...(합격 기준 전문)",
  "evidence_excerpt": "...(근거 원문 발췌 전문. E형은 null)",
  "citation": "...(근거 출처)",
  "acl_level": "all"
}
```
규칙:
- **id에 배치 접미 필수**(`@G-B1` 형식) — 배치 간 ID 중복(각 배치가 RC-A001부터 시작) 충돌 방지. 회수 후 원파일 역매핑 키가 된다.
- answer_type 빈값은 "single"로 채움. E형은 evidence_excerpt=null 명시.
- 값은 원문 그대로(요약·수정 금지). 셀 내 개행은 \n 보존.

### 배치 구성
- **1배치 = 30문항** → 총 30배치(마지막 배치 23문항). 파일명 `2axis_input_B01.json` ~ `B30.json`.
- 배치 경계는 원배치 순서대로 자름(G-B1부터). 각 파일 첫머리에 `{"batch":"B01","count":30,"items":[...]}` 구조.
- 별도 `2axis_manifest.md`: 배치별 문항 수·id 범위·원파일 매핑 표.

### 완료 보고 (등식)
- 총 893 = 30배치 합 (배치별 건수 표)
- id 전역 유일(@접미 포함) 중복 0
- E형 78건(=각 배치 E형 합) evidence null 확인
- 필드 결측 0 (9필드 × 893)

## PART B — 송하: Kimi 투입 절차

### 준비물
1. `judge_prompt_2axis_표준.md` (kit에 있음) — 판정 프롬프트
2. AI-3가 만든 `2axis_input_B01.json` ~ `B30.json`

### 실행 (배치당 1회, 총 30회)
1. Kimi **새 대화** 열기 (배치마다 새로 — 이전 판정이 다음 판정에 영향 주지 않게).
2. 첫 메시지: `judge_prompt_2axis_표준.md` 전문 붙여넣기 + 마지막에 한 줄 추가:
   > 아래 배치의 각 문항을 판정하고, 출력은 JSON 배열 하나로만 답하라. 문항 수와 판정 수가 일치해야 한다.
3. 같은 메시지(또는 바로 다음 메시지)에 `2axis_input_B0N.json` 내용 붙여넣기.
4. Kimi 출력(JSON 배열)을 복사해 `2axis_result_B0N.json`으로 저장.
5. **즉시 확인 2가지**: (a) 판정 개수 = 투입 개수(30), (b) 출력이 JSON 형식인지. 어긋나면 "누락된 id를 마저 판정하라"고 같은 대화에서 요청.
6. 30배치 결과를 모아 나(설계본부)에게 제출.

### 주의
- Kimi가 JSON 밖에 설명을 붙이면 무시하고 JSON만 저장하면 된다.
- 한 배치가 길어서 잘리면: "이어서 출력하라"로 나머지 회수.
- 하루에 다 안 해도 된다 — 배치 단위로 끊어져 있으니 나눠서 진행 가능.

### 회수 후 (설계본부가 할 일 — 참고)
1. 결과 30파일 실측: id 전수 대조(893, 누락·중복 0), verdict 분포 집계
2. 3차 교차검토(Gemini Pro)로 A/B/C 분류 — 사람 볼 것만 추림
3. 사람 확정 큐 구성 → 송하/김난희 최종 판정 → 검증상태 초안→검증완료 갱신
