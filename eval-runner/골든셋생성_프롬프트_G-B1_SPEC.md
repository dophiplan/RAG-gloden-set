# [작업 지시] RC 골든셋 생성 — G-B1 배치 (SPEC / 사양·가격·SDK)

너는 이 작업을 처음 받는 새 세션이다. 이 문서 + 첨부 파일만으로 완주하도록 설계됐다. 모르는 것은 지어내지 말고 `[확인 필요]`로 남겨 되묻는다. 산출·보고는 한국어, 코드 주석은 영어 무방.

---

## 0. 이 작업이 무엇인가 (배경)

회사 제품 RemoteCall(RC)의 RAG 시스템을 평가하기 위한 **골든셋**(질문-정답-근거로 된 평가 문항집)을 만든다. 재료는 이미 완성된 **커버리지맵**(제품이 아는 사실을 단위로 쪼갠 인벤토리)이다.

- 커버리지맵 = "무엇을 아는가"의 사실 목록 (재료)
- 골든셋 = 그 사실로 만든 "질문-정답-근거" 평가 문항 (네가 만들 것)

이번 배치는 **SPEC 원천**(사양·가격·SDK·요구사항 등)만 다룬다. 전체 원천 중 첫 배치다.

**핵심 원칙 (반드시 지킬 것):**
1. **정답 근거는 재료에 실재하는 사실만.** 커버리지맵의 "이 단위가 말하는 사실" 필드 + 정본 원문에 글자로 있는 것만 정답으로 쓴다. 네 제품 지식으로 지어내면 안 된다(그러면 RAG가 모르는 걸 묻는 잘못된 문항이 된다).
2. **질문은 사용자 언어로.** 사실 문장을 그대로 뒤집은 질문은 검색이 너무 쉬워 변별력이 없다. 고객이 실제 쓸 표현(구어체·동의어)으로 쓴다.
3. **함정(E형) 문항 포함.** "자료에 없는 것"을 일부러 물어 "지어내지 않고 모른다고 답하는가"를 시험하는 문항을 섞는다.
4. **신규 문항은 전부 검증 상태 = "AI 초안 / 검수 대기".** 너는 생성만 한다. 합격/확정은 다른 단계(검수자·사람)가 부여한다. "합격"이라 표기하지 마라.

## 2. 재료 필터 (정확히 이것만)

`최종통합_전체` 시트에서 **아래 조건을 모두 만족하는 행만** 재료로 쓴다:
- `Unit ID`가 `RC-SPEC-`로 시작
- `상태` == `미검토`

**실측 기준값: 정확히 220단위여야 한다.** (열어서 세어보고, 220이 아니면 멈추고 `[확인 필요]`로 보고.)

영역(3단) 분포 (검증용 — 이대로 나와야 정상):
```
SDK 38 · PRICE 31 · REQ 30 · MOBILE 27 · ONPREM 23 · WVSDK 12 ·
FEAT 9 · STENT 9 · STVPACK 9 · STMPACK 8 · STPRO 8 · API 5 ·
MOBAND 4 · CERT 4 · AGENT 1 · FUNC 1 · VISUAL 1
```

각 단위에서 쓸 필드: `이 단위가 말하는 사실`(정답 근거) · `답변 가능한 질문`(질문 착안점) · `source/resource`+`source_location`(근거 출처) · `citation_id`(근거 앵커) · `acl_level`(전부 "공개").

## 3. 만들 문항 (유형 배분)

SPEC은 "사양·버전" 성향이다. 방법론 §3·사례B에 따라 **A(사실 조회) 우세 + 버전/경계 G + 함정 E**로 배분한다. 권장 목표:

| 유형 | 비중 | 설명 |
|---|---|---|
| A. 단순 조회 | ~55% | 사양값·가격·지원 범위 등 사실 확인 |
| C. 복합 | ~10% | 두 사양을 견주거나 조건 결합 |
| D. 멀티홉 | ~10% | 여러 단위를 엮어야 결론 (예: 에디션별 세션 한도 → 초과 시나리오) |
| E. 무응답 함정 | ~15% | 미래 버전·미기재 사양 등 "자료에 없음"이 정답 |
| G. 경계·예외 | ~10% | 버전 컷오프, 지원/미지원 경계 |

- **목표 문항 수: SPEC 220단위 전수 커버 기준 약 180~250문항** (1단위=1문항이 원칙이나, 동질 사양은 대표 묶음 가능·중복은 보류. 억지로 숫자 맞추지 말 것 — 방법론 §6-5).
- **커버 목표: SPEC 220단위 전부가 최소 1문항에 근거로 쓰이거나, 대표 묶음/제외 사유가 명시돼야 한다(문서 수준 커버 100%).**
- E형은 재료에 **없는** 것을 묻는 것이라 특정 단위에 매이지 않는다(별도 설계).

## 4. 출력 스키마 (13컬럼 — 생성규칙서와 동일)

시트 `골든셋_SPEC`, 컬럼 순서 고정:

| # | 컬럼 | 내용 |
|---|---|---|
| 1 | ID | `RC-{유형접두}##` (예: A형 `RC-A001`, E형 `RC-E001`). 전역 유일 |
| 2 | 유형 | `A. 단순 문서 조회` 등 생성규칙서 표기 |
| 3 | 출제 의도 | 무엇을 시험하는지 한 줄 |
| 4 | 질문 | 사용자 언어 질문 |
| 5 | 정답 (필수 포함 요소) | 정답 + "필수: {반드시 포함돼야 할 핵심 수치/사실}" |
| 6 | 근거 출처 | source/resource URL + source_location (+ citation_id) |
| 7 | 합격 기준 | 예: `근거 top-5 내 AND Faithfulness≥4 AND Correctness≥4 / 필수: {요소}`. E형은 knock-out 게이트 |
| 8 | 난이도 | 하/중/상 |
| 9 | 기대 라우팅 | 문서검색 / 거절 / 하위질의분할 등 |
| 10 | 검증 상태 | **전부 "AI 초안 / 검수 대기"** |
| 11 | 작성자/검증자 | "AI 초안 / 사람 검수 대기" |
| 12 | 근거 원문 발췌 | 재료 사실 필드에서 근거가 되는 원문 조각 (정답 전체가 아니라 대조점) |
| 13 | 신뢰도 | 높음/중/낮음 (+ 근거 수) |

추가 시트:
- `커버리지_대조`: SPEC 220단위 × (문항ID 매핑 / 대표묶음 / 제외사유) — 문서 수준 커버 100% 증명
- `사람확인`: 원문 충돌·모호·근거 부족으로 사람이 봐야 할 것 (E형 역검색 확인 포함)
- `작업보고`: §5 완료 보고

## 5. 완료 보고 (숫자 없는 완료는 반려된다)

코드로 직접 세어 실측 숫자로 보고하라:
1. **재료 검증**: SPEC 미검토 단위 = 220 (일치 여부). 영역 분포 = §2와 일치.
2. **문항 수**: 총 N문항. 유형별 분포(A/C/D/E/G 각 건수·%).
3. **커버 등식**: SPEC 220단위 중 문항 근거로 쓰인 단위 수 + 대표묶음 흡수 수 + 제외 수 = 220 (소실 0).
4. **근거 실재 검증**: 모든 A/C/D/G 문항의 근거 발췌가 재료 사실 필드에 문자로 실재하는지 (1축 자가 점검, 잔존 0). E형은 역검색으로 "재료에 없음" 확인.
5. **정답 누설 점검**: 질문 안에 정답이 그대로 노출된 문항 0.
6. **검증 상태**: 전 문항 "AI 초안 / 검수 대기" (예외 0).
7. **사람확인 건수**: 충돌·모호·근거부족 목록 수.

애매하거나 근거가 부족한 문항은 만들지 말고 `사람확인` 시트로 빼라(억지 생성 금지). 등식이 안 맞으면 원인 찾아 보고하고 멈춘다(임의 보정 금지).

---

## 6. 첫 응답으로 할 것

1. 첨부 5개 확인, 생성규칙서·방법론(§3·사례B) 통독.
2. 재료 필터 실행 → SPEC 미검토 220단위 확인(§5-1). 220 아니면 멈추고 보고.
3. 유형 배분 계획을 표로 먼저 제시 (몇 문항, 유형별 몇 개, 커버 방식). **이 계획을 보고하고 승인을 기다린 뒤 본 생성에 들어가라** — 계획 선승인이 원칙이다.
4. 승인 후 문항 생성 → §4 스키마로 빌드 → §5 전 항목 실측 보고.
