# 알피스 골든셋 작성 키트 — v0.3 보완 패치

> **이 문서는 `RAG_골든데이터셋_작성키트_v0.2.docx`에 덧붙이는 개정 노트다.**
> v0.2 본문은 그대로 유효하고, 아래 5개 항목만 **추가·교체**해서 쓴다.
> 보완 근거: 사내 4제품(RC·RV·RM·HR) 골든셋 구축에서 실제로 터진 사고 5종을 미리 막기 위함.
> 작성: 2026-07-07 · v0.2 → v0.3

---

## 왜 보완하나 — 한 줄

v0.2 키트는 **평가 설계(루브릭·라우팅·SQL·게이트)가 훌륭하다.** 그대로 쓴다.
다만 사내 다른 제품 골든셋을 만들며 **"문항 데이터 자체가 오염되는" 사고 5종**을 겪었고, 그 백신을 여기 이식한다.

---

## 보완 1. 스키마에 `answer_type` 컬럼 추가 (11컬럼 → 12컬럼)

**문제:** 정답이 여러 개 다 맞는 문항(예: "휴가 신청 경로?" → 그룹웨어로도, 인사시스템으로도 가능)을 정답 하나만 적으면, 맞는 답을 한 시스템을 **틀렸다고 오채점**한다. (RC·RM에서 실제 발생)

**보완:** 3장 스키마에 **12번 컬럼 `answer_type`** 추가.
- `single` = 정답이 사실상 하나
- `multi_equivalent` = 여러 답이 모두 정답 (어느 하나만 맞혀도 통과)
- 비면 `single`로 간주

**채점 연동:** `multi_equivalent` 문항은 "목록 중 하나와 의미상 일치하면 정답"으로 채점. Judge 프롬프트에도 이 분기를 넣는다.
**⚠️ 가드:** "여러 답이 다 맞음(multi)"과 "하나만 맞는데 안 가림(충돌)"을 절대 섞지 마라. 충돌은 multi가 아니라 v0.2의 충돌 목록 시트로.

## 보완 2. 유형에 G(경계/예외) 추가 — 6유형 → 7유형

**문제:** v0.2는 A~F 6유형이다. 그런데 알피스가 검색할 사내 문서(RC 기능표·사양서 등)는 **"버전·OS·에디션별로 되고 안 되는" 경계 지식**이 대량이다. 이걸 A(단순조회)로 뭉뚱그리면 "Win에선 되는데 Mac에선 안 되는" 비대칭을 평가하지 못한다.

**보완:** 유형 **G. 경계/예외** 추가.
- 출제 의도: 버전·OS·에디션·플랫폼별로 **다르게 동작하는 경계**를 정확히 아는가
- 예: "안전모드 재접속은 Mac→Win 환경에서 지원되나요?" (표에 X로 명시)
- 합격 기준: 경계 조건(어디까지 되고 어디부터 안 되는지)을 정확히, 혼동 시 0점
- 비중: 사내 제품 문서 비중이 크면 A에서 일부를 G로 재배분 (기능표·사양서 중심 카테고리)

> 사내 4제품 표준은 A~G 7유형을 쓴다. 알피스도 G를 넣으면 사내 자산(아래 보완 5)과 유형이 맞아 재사용이 쉬워진다.

## 보완 3. E형·G형 근거 처리 명확화

**문제:** "미지원"을 어떻게 처리할지 애매해 오분류가 났다. (RC에서 E형 197건이 통째로 오분류)

**보완 — 딱 두 줄로 구분:**
- **원문에 "미지원/X/제한"이 명시돼 있다** → 그건 근거 있는 **사실**이다 → **A 또는 G형** (발췌 = 그 X 표시가 있는 셀/문장)
- **원문 어디에도 그 정보가 아예 없다** → 그때만 **E형**(무응답 함정) → **발췌 칸은 반드시 공란**

> 헷갈리면 자문: "원문에 답이 적혀 있나?" 적혀 있으면(설령 '안 됨'이라도) E가 아니다.

## 보완 4. 질문 유일성 + 원천 빈 값 규칙 (문항 품질 2종)

**문제 A (질문 중복):** 템플릿으로 찍어내다 "OS 지원 기능은 어떤 조건에서 되나요?" 같은 **똑같은 질문이 24번** 나왔다. RAG에 물으면 어느 걸 정답으로 볼지 특정 불가. (RC 332건)
**보완 A:** 질문 텍스트만 읽고 **어느 사실을 묻는지 특정**되게. 섹션명이 아니라 실제 기능명·OS·버전·플랫폼 조건을 질문에 넣는다. 동일 질문 텍스트 중복 금지.

**문제 B (빈 값):** 원천 셀이 비었는데 그 빈 값이 정답에 그대로 들어갔다("최소지원: ,"). (RC 20건)
**보완 B:** 원천 셀이 비어 있으면 그 값을 정답에 넣지 마라. 그 문항은 만들지 말고 근거 확보를 **검증 상태 = 미검증(사람확인)** 으로 남긴다.

## 보완 5. ★ 사내 자산 재사용 — 근거를 처음부터 다시 찾지 마라

**문제:** v0.2 키트의 근거 문서(RC 상담원 매뉴얼·RV 관리자 매뉴얼·사양서 등)는 **사내에서 이미 커버리지맵으로 전수 분해**돼 있다. 새로 뒤지면 중복 작업 + 근거 불일치.

**보완:** 다음 사내 자산이 있으면 **정답·근거의 1차 소스로 우선 사용**한다 (없으면 v0.2대로 원문 직접):
- `RC_커버리지맵_통합정본` (사양서·매뉴얼·KnownIssue 1,367단위, 각 단위에 근거 발췌 포함)
- `RV_커버리지맵_OKF_v0.4` / `RM_커버리지맵` / `인사팀_커버리지맵`
- 각 단위의 `citation_id`(Unit ID)를 근거 출처 칸에 적으면, 나중에 검색 평가(레이어1) 매핑이 자동으로 이어진다.

> 즉 알피스 100문항 중 사내 제품 관련 문항은 **이미 분해된 사실에서 골라 오면** 되고, 그게 근거의 진본성도 보장한다.
