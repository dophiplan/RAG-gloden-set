# [제품 기획서] 통합 지식 플랫폼 (가칭)

> 한 줄 정의: 제품마다 RAG를 따로 만들지 않고, **공용 RAG 엔진 1개** 위에 **제품별 프로세스**를 얹어
> 그 위에서 **묻고 · 시키고 · 되먹이는** 사내·제품 공용 지식 플랫폼.
> (개념 상세는 별첨 "통합 지식 플랫폼 — 큰 그림" 참조.)

---

## 1. 추진 배경 & 문제 정의

회사 내부에 RAG(검색 기반 AI)가 **팀·제품별로 따로** 구축되고 있다.

- 배재원 팀 — Agentic RAG 엔진 (OpenSearch 기반, 회의록 도메인)
- AI팀 — RAG 고도화 방향서 (Weaviate 기반, 한국어 검색 최적화)
- RemoteCall — 상담·진단 RAG + 학습 루프
- 이호경 — 위키 기반 개발 지식(LLMS)

→ **같은 것을 여러 번 만드는 중복 투자**, 지식 단절, 유지보수 분산이 일어나고 있다.
→ 동시에 RAG는 제품 경쟁력의 핵심(RC AI 상담·진단)으로 올라서고 있다.
→ 따라서 **공용 엔진 + 제품별 프로세스**로 통합할 시점이다.

---

## 2. 목표 / 비(非)목표

**목표**
- 공용 RAG 엔진 1개 위에 제품별 프로세스를 얹어 **묻기·시키기·되먹이기**를 제공하는 통합 지식 플랫폼 구축.
- 기존 자산(배재원 엔진)을 공용 코어로 재사용.

**비목표 (이번 범위 아님)**
- 전 제품 동시 전환 — 한 제품에서 검증 후 확장.
- 신규 엔진 자체 개발 — **기존 엔진을 쓴다.**
- 대규모 운영 배포 — 초기는 검증(PoC) 중심.

---

## 3. 제품 컨셉 (요약)

- **1엔진 N프로세스** — 엔진은 공용 하나, 프로세스는 제품마다.
- **허브 + 임베드** — 중앙 관리 콘솔(거버넌스·승인·모니터링) + 제품 내 묻기·시키기 패널.
- **세 동작** — 묻기(읽고 답) / 시키기(써서 행동) / 되먹이기(결과를 지식으로 환원).

---

## 4. 추진 전략 — 5단계 (각 단계 = 검증 게이트)

| 단계 | 목표 | 핵심 산출물 | 완료 조건(검증) |
| -- | -- | -- | -- |
| **1** | 엔진 범용성 검증 + 지식 표준 | 엔진 PoC 결과, 거버넌스 규칙 초안 | 비-회의록 문서로 **묻기**가 출처 포함 정상 동작 / 한국어 검색 품질 점검 |
| **2** | 첫 제품 × 묻기 | 제품 내 묻기 패널(예: RC 상담원) | 실제 사용자가 쓰는 묻기 동작 + 사용 로그 |
| **3** | 시키기 추가 | 명령·조치 실행 + 안전장치 | 권한·실행 전 확인·실행 이력(감사) 동작 |
| **4** | 되먹이기 + 거버넌스 | 승인 큐, 중앙 콘솔 1차 | 쓴 결과가 검수 후 지식에 반영되는 루프 동작 |
| **5** | 제품 확장 + 플랫폼화 | N제품 연결, 모니터링 | 2개 이상 제품이 같은 엔진 사용, 멀티테넌시·지표 |

원칙: 안전한 것(묻기) → 위험한 것(시키기) → 복리(되먹이기), 한 제품 검증 → N제품 확장.
**1~3 = 증명 단계, 4~5 = 통합 값어치 실현 단계.**

---

## 5. 기대 효과

1. **사람한테 묶인 지식 해방** — 담당자 부재·퇴사에도 업무 지속, 온보딩 단축.
2. **중복 제거** — 엔진 1개 공용화로 개발·운영비 절감.
3. **지식의 복리** — 되먹이기 = 경쟁사가 못 베끼는 해자.
4. **운영 효율** — 응답 속도·비용·처리량 개선.
5. **제품 경쟁력** — 안으로 효율, 밖으로 팔리는 기능.

## 6. 필요 자원 & 협조

| 항목 | 내용 | 협조 대상 |
| -- | -- | -- |
| 공용 엔진 | "배재원 엔진을 공용 코어로" 합의 + 접근/실행법 | 본부장, 배재원 팀 |
| 한국어 검색 품질 | AI팀 RAG 고도화 방향서 = **엔진 품질 체크리스트** | AI팀 |
| 지식 입력 표준 | 위키·llms.txt·문서 동기화 규율 | 이호경(연구소) |
| 거버넌스 | 지식 검수·승인 주체 지정 | 기획/운영 |
| 개발 | Claude Code 활용(Phase 1 핸드오프 브리프 기반) | 기획자 + 개발 |

---

## 7. 리스크 & 대응

| 리스크 | 대응 |
| -- | -- |
| 거버넌스 부재 → 누적이 노이즈가 됨 | 되먹이기 **승인 게이트** 필수 |
| 제품들이 엔진을 각자 포크 → ROI 소멸 | **공용화 합의 선행**, 콘솔로 공유 강제 |
| 엔진이 회의록 전용일 수도 | **1단계에서 범용성 검증** 게이트 |
| 한국어 짧은 쿼리 검색 불안정 | AI팀 체크리스트(형태소·하이브리드·리랭킹)로 점검 |
| 시키기가 실제 변경을 일으킴 | 권한·실행 전 확인·감사·롤백 |

## 8. 즉시 액션 (계획자 출발선)

- [ ] **정렬 미팅** — 본부장·배재원·AI팀: "배재원 엔진을 공용 코어로 삼는다" 합의
- [ ] **1단계 검증 준비** — 테스트용 도메인 문서 세트 + 샘플 질문 + 한국어 품질 체크리스트
- [ ] **거버넌스 주체 지정** — 지식 검수·승인 담당
- [ ] **Phase 1 착수** — Claude Code에 핸드오프 브리프 전달 (SRS·계획 먼저 확인 게이트)
