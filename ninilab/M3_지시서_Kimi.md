> **이번엔 통째다.** M3 전체를 한 번에 만든다. Kimi가 여러 파일을 만들어 "실제로 만지는 화면"을 낸다.
> 같이 첨부: 이 지시서 + `tree.ts` + `adapter.ts` + `editor.ts` + `export.ts` + `diff.ts` + `describe.ts` (검증 완료된 6개).

## 0. 전체 지도 — 당신은 지금 여기 있습니다

이 프로젝트는 **"디자인이 곧 코드가 되는 디자인 툴"**이다. 기획·디자인·개발이 같은 단일 원본(JSON 트리)을 보고, 화면·코드·이력 세 얼굴로 비친다. 궁극 목표는 **목업·스토리보드·프로토타입**을 한 도구에서.

```
M0  화면에 상자 그리면 JSON 된다              ✅ 완료 (tree, adapter, editor)
M1  트리 → HTML/CSS 출력                     ✅ 완료 (export)
M2  변경하면 이력이 남는다 (해자)              ✅ 완료 (diff, describe)
M3  여러 페이지 + 통합 화면 + 연결       ★ 당신은 여기 (통째)
M4  디자인 토큰 + AI로 편집
M5  저장·프로젝트·에러
```

지금까지는 **엔진 부품**만 따로 있었다(화면 1개 기준). M3는 두 가지를 한다:
1. 부품들을 **하나의 실제 화면**으로 조립 (사람이 만지는 UI)
2. "화면 1개"를 **"여러 페이지를 담는 프로젝트"**로 넓히고, 페이지를 **연결**(버튼 누르면 이동)

이게 되면 **목업(페이지 렌더) + 스토리보드(페이지 목록) + 프로토타입(눌러서 이동)** 세 개가 다 살아난다.

## 1. 무엇을 만드나 — 4덩어리

### ① `project.ts` — 여러 페이지를 담는 그릇 (새 파일)
지금 트리는 "화면 1개(루트 container)"다. 그 위에 **프로젝트**를 씌운다.

```typescript
import { type ContainerElement, type Element, createContainer } from "./tree.ts";

export interface Page {
  id: string;              // 고유 id (el_ 형식 재사용)
  name: string;            // "로그인 페이지" 등
  root: ContainerElement;  // 이 페이지의 화면 트리 (지금까지의 그 트리)
}

export interface Project {
  id: string;
  name: string;
  pages: Page[];
  // tokens 는 M4에서. 지금은 자리만 비워두거나 생략.
}

// 프로젝트 조작 함수 (순수 데이터, DOM 없음)
export function createProject(name: string): Project;         // 빈 페이지 1개로 시작
export function addPage(project: Project, name?: string): Page; // 새 빈 페이지 추가
export function removePage(project: Project, pageId: string): boolean; // 삭제(최소 1개는 남김)
export function findPage(project: Project, pageId: string): Page | null;
export function renamePage(project: Project, pageId: string, name: string): boolean;
```

- 새 페이지 = 빈 루트 container 하나 가진 Page. (createContainer 재사용)
- **id 규칙은 tree.ts와 동일하게** (el_ 형식). 페이지도 고유 id.

### ② 부품 연결 — 편집은 "현재 페이지"에 대해
- Editor(editor.ts)는 지금 트리 하나를 편집한다. → **현재 선택된 페이지의 root**를 Editor에 물려서 편집.
- 페이지 전환 = Editor의 대상 트리를 그 페이지 root로 바꾸는 것.
- 렌더는 adapter, 코드뷰는 export, 이력은 diff+describe 그대로 사용.

### ③ 통합 화면 — `demo-m3.html` (실제 만지는 UI)
브라우저에서 여는 단일 HTML. 레이아웃:

```
┌────────────────────────────────────────────────────────┐
│  상단바: 프로젝트명 · [편집모드 | 프리뷰모드] 토글          │
├──────────┬───────────────────────────┬─────────────────┤
│ 왼쪽      │  가운데: 캔버스              │ 오른쪽 탭:        │
│ 팔레트    │  (현재 페이지 렌더)          │ [코드] [이력]     │
│ +상자     │  + 보조선 격자(on/off)       │                 │
│ +텍스트   │                            │ 코드: export.ts  │
│ +버튼     │  요소 클릭 → 선택            │  실시간 HTML     │
│ +이미지   │  선택 후 팔레트로 안에 넣기    │ 이력: describe   │
│ +입력칸   │                            │  변경 사람말+되돌리기│
├──────────┴───────────────────────────┴─────────────────┤
│ 아래: 페이지 목록  [페이지1][페이지2] … [+ 새 페이지]      │
│        - 탭 클릭 → 그 페이지로 전환                        │
│        - 현재 페이지 강조                                  │
└────────────────────────────────────────────────────────┘
```

- **왼쪽 팔레트:** 요소 추가 버튼들. (선택된 상자 안에 넣기 — editor.addText/addInput/addEmptyContainer 등)
- **가운데 캔버스:** 현재 페이지를 adapter로 렌더. 요소 클릭하면 선택. **보조선 격자 토글**(순수 배경 안내선, 데이터엔 안 들어감 — 09 원칙).
- **오른쪽 [코드] 탭:** 현재 페이지를 export.ts로 HTML/CSS 실시간 표시.
- **오른쪽 [이력] 탭:** 편집 전/후 스냅샷을 diff→describe로 사람말 목록 + **되돌리기**(아래 ④에 통합).
- **아래 페이지 목록:** 스토리보드처럼 페이지들 나열. 클릭 전환, [+ 새 페이지]로 추가.

### ④ 페이지 연결(action) + 이력/되돌리기 — 프로토타입의 심장
**연결(action):**
- 버튼(input/button)을 선택하면 오른쪽 속성에 **"누르면 이동할 페이지"** 선택칸.
- 선택하면 그 버튼에 `action: { onClick:"goToPage", target: 페이지id }` 저장. (14번 설계)
- **프리뷰 모드**(상단 토글): 이 모드에선 버튼을 실제로 누르면 target 페이지로 전환된다. → **프로토타입 동작.**
- 편집 모드에선 버튼 눌러도 이동 안 하고 선택만.

**이력/되돌리기 (M2-3 통합):**
- 각 편집 후 스냅샷을 스택에 쌓는다: `{ pageId, before, after, changes(describe 결과), 시각 }`.
- 이력 탭에 최근 변경들을 사람말로 표시.
- **되돌리기 버튼:** 마지막 변경을 취소 (해당 페이지를 before 스냅샷으로 복원). 여러 번 누르면 계속 뒤로.
- (author는 지금 "local" 고정. 07의 예약 자리만 채움.)

## 2. 핵심 원칙 (어기면 방향 틀림)

- **진실은 데이터(Project→Page→트리)에 있다.** 화면은 그 렌더일 뿐. (02 원칙)
- **절대좌표 금지 유지.** 캔버스에서 요소를 픽셀로 드래그 배치 ❌. 상자에 넣고 순서/크기(레고 자유)로만. (00 원칙)
- **보조선 격자는 눈에만.** 격자 칸을 좌표로 저장하지 마라. 위치는 여전히 구조 트리. (09 원칙)
- **페이지 하나하나는 지금 트리 그대로.** 프로젝트는 그 위 그릇일 뿐. (01 원칙)
- **토큰은 M3 범위 아님.** 색은 지금처럼 값 직접. (토큰은 M4)

## 3. 합격 기준 (체크리스트)

**여러 페이지**
- [ ] 새 페이지를 추가할 수 있다 (아래 [+ 새 페이지])
- [ ] 페이지 탭 클릭하면 그 페이지로 전환되고 캔버스가 바뀐다
- [ ] 페이지를 삭제할 수 있다 (단 최소 1개는 남음)
- [ ] 각 페이지가 독립된 트리를 가진다 (한 페이지 편집이 다른 페이지에 영향 없음)

**통합 편집**
- [ ] 팔레트로 상자/텍스트/버튼/이미지/입력칸을 선택된 상자 안에 넣을 수 있다
- [ ] 요소 클릭하면 선택된다
- [ ] 오른쪽 [코드] 탭에 현재 페이지 HTML/CSS가 실시간 표시된다
- [ ] 보조선 격자를 켜고 끌 수 있다 (데이터엔 영향 없음)

**연결 / 프로토타입**
- [ ] 버튼에 "누르면 이동할 페이지"를 지정할 수 있다 (action 저장)
- [ ] 프리뷰 모드에서 그 버튼을 누르면 target 페이지로 실제 전환된다
- [ ] 편집 모드에선 버튼 눌러도 이동 안 하고 선택만 된다

**이력 / 되돌리기**
- [ ] 편집하면 이력 탭에 사람말로 뜬다 ("○○의 라벨을 …로 바꿈")
- [ ] 되돌리기로 마지막 변경을 취소할 수 있다
- [ ] 되돌리면 캔버스·코드도 같이 되돌아간다

**기본기**
- [ ] JSON 어디에도 절대좌표(x/y/top/left/position) 없음
- [ ] 첨부 6개 부품을 import해서 씀 (재구현 ❌)

## 4. 하지 말 것

- **디자인 토큰(basic-color 등) 만들지 마라.** M4 일. 색은 값 직접.
- **AI/채팅 편집 만들지 마라.** M5 일.
- **자유 좌표 드래그 만들지 마라.** 상자+구조로만.
- **격자 칸을 좌표로 저장하지 마라.** 격자는 배경 안내선일 뿐.
- **웹페이지 import·완전자동 컴포넌트화 만들지 마라.** 보류(06).
- 첨부 부품(tree/adapter/editor/export/diff/describe)을 **재구현하지 마라.** import해서 연결만. (불가피한 수정은 표시)
